# LowLife

pyRevit-расширение для проектирования слаботочных систем (СКС, СКУД, СПС, СОУЭ, СПА) в Autodesk Revit: скрипты IronPython/CPython 2, запускаются внутри Revit через pyRevit.

## Установка

Добавьте расширение в pyRevit по ссылке на этот репозиторий (Extensions → Add from GitHub URL). pyRevit сам клонирует репозиторий в `%APPDATA%\pyRevit\Extensions\LowLife.extension\` — вкладка `LowLife.tab` должна оставаться в корне репозитория, отдельной папки-обёртки `.extension` в самом репозитории нет и быть не должно.

Обновление — повторный pull через менеджер расширений pyRevit и перезагрузка pyRevit / перезапуск Revit.

## Поддерживаемые версии Revit

| Версия Revit | Статус |
|---|---|
| 2024 | основная рабочая версия — на ней проверяется поведение API |
| 2025, 2026 | поддерживается: учтён переход Revit на .NET 8 (открытие ссылок, Outlook, завершение процессов) |
| 2022–2023 | должно работать: там, где API менялся, есть откаты на старые вызовы (`ElementId.IntegerValue`, `ParameterType`), но отдельно не проверялось |
| 2021 и старше | не поддерживается |

Жёсткого ограничения по версии в кнопках нет (`min_revit_version`/`max_revit_version` не заданы): расширение загрузится в любой Revit, который поддерживает установленный pyRevit. Скрипты написаны на IronPython 2 и рассчитаны на стандартный движок pyRevit, поэтому нужна версия pyRevit, поддерживающая вашу версию Revit (для Revit 2025+ — pyRevit 5.x).

Эти же сведения и ваша текущая версия Revit показаны в окне «О программе» (первая кнопка ленты). Если меняете таблицу, поправьте и `REVIT_SUPPORT` в `lib/lowlife/about.py`.

## Параметры

Какие параметры должны быть у каких типов устройств (узлов трассы, устройств, панелей, электрических цепей, схемных семейств, видов) для каждой дисциплины — в сводной таблице [docs/parameters.md](docs/parameters.md). Ссылка на неё есть и в окне «О программе».

## Панели и кнопки

Первая панель ленты — **LowLife**: кнопка с логотипом открывает окно «О программе» (версия расширения — коммит, из которого pyRevit его поставил, и ссылка на репозиторий), кнопка «Обратная связь» — сообщить автору о проблеме или предложить улучшение (выбор панели и кнопки + описание; сообщения уходят в Google Таблицу автора, см. [`docs/feedback-panel.md`](docs/feedback-panel.md)). Рядом выпадающий список «Тема» — он переключает, какие панели/кнопки видны на ленте — по дисциплине (СКС/СКУД/СОТ/СОУЭ/СПС/СПА) или по группе (КНК — лотки, Электрические цепи, Настройки, Общее, Служебное). У большинства рабочих кнопок есть Shift+клик — открывает настройки именно этой кнопки (единого окна настроек на панель нет).

<details>
<summary><b>SCS</b> — структурированная кабельная система</summary>

- **Узлы трассы** — расставляет панели/узлы маршрута/стояки в точках трассы кабеля.
- **Адреса узлов** — нумерует адреса узлов маршрута по этажу, начиная от панелей/стояков.
- **Расчёт длины цепи** — считает длины кабеля по трассе и номера/маршруты цепей для целевых панелей.
- **Структурная схема** — строит/обновляет структурную схему СКС: своя цветная шина (коллектор + стояк) на каждую панель, инкрементальное обновление при повторном запуске.
- **Маршрут цепи** — подсвечивает на модели маршрут выбранной цепи СКС (для проверки).
- **Привязка параметров** — проверяет/добавляет привязку параметров СКС к категориям из подключённого файла общих параметров (ФОП).
</details>

<details>
<summary><b>SKUD</b> — система контроля и управления доступом</summary>

- **Узлы трассы СКУД** — расставляет узлы маршрута/стояки СКУД (свои, отдельные от узлов СКС).
- **Адреса узлов СКУД** — нумерует адреса узлов трассы СКУД от контроллеров/стояков.
- **Цепи и кабели** — назначает устройствам адрес, тип проводника и имя нагрузки, маркирует контроллеры.
- **Длины и маркировка** — считает длину проводника каждой цепи контроллер → устройство.
- **Помещение точек прохода** — проставляет устройствам СКУД одно общее помещение на точку прохода.
- **Точки доступа на двери** — расставляет элементы точки доступа (считыватель, замок, доводчик, геркон, кнопки, домофон) на двери выбранных помещений по мнемосхеме двери; Shift+клик — мнемосхема и типы точек доступа.
- **Структурная схема** — строит/обновляет структурную схему СКУД, инкрементально.
- **Маршрут цепи** — подсвечивает на модели маршрут выбранной цепи СКУД.
- **Диагностика: Устройства схемы** — тестовая кнопка: показывает цепи и устройства выбранного контроллера.
- **Привязка параметров** — проверяет/добавляет привязку параметров СКУД к категориям из ФОП.
</details>

<details>
<summary><b>SOT</b> — охранное телевидение</summary>

- **Навести на помещение** — рассчитывает и записывает наклон камеры по границе помещения.
- **Зоны обзора** — строит зону обзора камеры (заливкой), обрезанную по границе помещения.
- **Структурная схема** — строит/обновляет структурную схему СОТ, инкрементально.
- **Вид как с камеры** — создаёт/обновляет 3D-перспективный вид из точки камеры с её азимутом, наклоном и полем зрения.
- **Проверка параметров** — диагностика: какие параметры выбранной камеры подходят под роли расчёта зоны обзора, откуда берётся ориентация, разбор семейства. Модель не меняет.
</details>

<details>
<summary><b>SOUE</b> — оповещение и управление эвакуацией</summary>

- **Цепи шлейфов** — создаёт по одной электрической цепи на каждый шлейф и подключает к его панели.
- **Длины шлейфов** — считает длину каждого шлейфа по координатам устройств, маркирует их.
</details>

<details>
<summary><b>SPS</b> — пожарная сигнализация</summary>

- **Структурная схема СПС** — строит/обновляет структурную схему, включая ветви изоляторов и кольца шлейфов, инкрементально.
- **Длины шлейфов** — считает длину каждого шлейфа по координатам устройств.
- **Маршрут цепи** — подсвечивает на модели маршрут (дерево) выбранного шлейфа.
- **Диагностика коннекторов** — тестовая кнопка: показывает категории и электрические коннекторы выбранных элементов.
</details>

<details>
<summary><b>SPA</b> — пожарная автоматика</summary>

- **Расстановка РМ, АМ, МДУ** — ставит сопутствующее устройство рядом с каждым настроенным базовым объектом, со смещением и переносом параметров.
</details>

<details>
<summary><b>Schematic</b> — черновые схемы</summary>

- **Рыба структурной схемы** — строит черновую структурную схему по помещениям (а не по устройствам): в одном окне для каждого этажа пишете, как показать помещение на схеме (одинаковая подпись — общий бокс); типовые этажи заполняются сами, подписи запоминаются.
</details>

<details>
<summary><b>LOI</b> — заполнение параметров по контексту</summary>

- **Заполнение LOI** — клонирует параметры из элементов категории «Формы» в элементы, попадающие в солид формы (в т.ч. из связей); линейные элементы на границе форм разрезаются, неразрешённое — в таблицу конфликтов.
- **Заполнение этажа** — пишет в настроенный параметр значение по уровню элемента (таблица «Уровень / Значение» в Shift+клик).
- **Обновить имя уровня** — назначает опорный уровень выбранным экземплярам семейств без уровня и без основы (уровень из списка или по высоте); если Revit не даёт поменять параметр «Уровень», пересоздаёт экземпляр на том же месте с переносом параметров и цепей.
</details>

<details>
<summary><b>Электрические цепи</b> — CircuitsSCS / CircuitsSKUD / CircuitsSPS / CircuitsSPA / CircuitsGeneric / CircuitsDelete</summary>

- **Цепи СКС** — строит цепи СКС между панелью и устройствами (по коннектору на цепь, домашний прогон).
- **Цепи СКУД** — ручное построение цепей панель (контроллер) → устройство.
- **Цепи шлейфов СПС** — создаёт по цепи на каждый шлейф СПС и подключает к панели.
- **Цепи изолятор-устройства СПС** — строит цепи между изолятором и выбранными устройствами.
- **Цепи шлейфов СПА** — строит цепи СПА по адресу устройства (как СПС, рабочий набор с ключевым словом «СПА»).
- **Длины шлейфов СПА** — считает длину каждого шлейфа СПА по координатам устройств.
- **Цепь (общее)** — строит произвольные цепи панель → устройства целиком по настройкам, без зашитой логики дисциплины.
- **Удалить цепи на виде** — удаляет все цепи, у которых хотя бы один элемент виден на активном виде.
- **Подсветить без цепи** — подсвечивает на активном виде элементы с электрическими коннекторами, у которых ещё нет цепи; подсветка снимается сама по мере создания цепей. Shift+клик — снять подсветку сразу, не дожидаясь этого.
</details>

<details>
<summary><b>Кабельные лотки</b> — TrayLadder / TrayPerforated / TrayUnperforated / TrayWire / TrayRoof / ToolsTraySection</summary>

Пять панелей (Лестничный / Перфорированный / Неперфорированный / Проволочный / на кровле), в каждой — четыре одинаковые по смыслу кнопки **Лоток СБ / СПЗо / СПЗп / СС**: переключают рабочий набор на содержащий «КНК» и вставляют кабельный лоток соответствующего профиля и типа.

- **Сечение лотка** (ToolsTraySection) — строит на чертёжном виде сечение лотка с фактической раскладкой кабелей (гравитационная упаковка кругов) по данным из Excel.
</details>

<details>
<summary><b>Tools</b> — общие инструменты</summary>

- **ID элемента** — показывает и копирует в буфер ID выбранного элемента, в т.ч. внутри связанной модели.
- **Размеры осей** — образмеривает выбранные оси на виде.
- **Длина линий** — сумма длин выбранных обобщённых моделей по типам.
- **Разрез по семейству** — строит обрезанный разрез по выбранному семейству или линейному системному элементу (лоток, короб, труба, стена) с шаблоном вида, типоразмером и именем по маске; по высоте — до следующего этажа того же корпуса, для нескольких элементов — один общий разрез или по разрезу на каждый.
- **Марки оборудования** — ставит недостающие марки оборудования на активном виде и раскладывает их ровно и без пересечений (стопкой/колонкой с выносками-полками). Подробнее — `docs/equipment-tags.md`.
- **Обход линий** — строит дугу обхода заданного диаметра на пересечениях линий детализации (одиночный/множественный режим).
- **Лотки связи в Эксель** — выгружает в .xlsx кабельные лотки связанной модели, видимые на активном виде (ID, тип, отметка, уровень, связь).
- **Проверка орфографии** — отправляет тексты заметок (выделенных, на виде или во всей модели) в ИИ и исправляет орфографию, грамматику и пунктуацию; исправления показываются списком «было → стало», записываются только отмеченные, форматирование заметок сохраняется. ИИ — тот же, что у «Задач из почты» (подключение общее). Подробнее — [docs/spellcheck.md](docs/spellcheck.md).
- **Привет** — тестовая кнопка.
- **Зум к элементу** — приближает вид к выбранному элементу или элементу по ID.
</details>

<details>
<summary><b>ToolsExport</b> — выгрузка</summary>

- **Переименование выгрузки** — меняет «0000» на «000» в именах выгруженных файлов (DWG/PDF); умеет автозапускаться после экспорта в ModPlus.
- **Переименование по списку** — переименовывает файлы по таблице соответствий между двумя папками с одинаковыми именами.
- **Поймать id команды** — диагностическая кнопка: определяет id нажатой кнопки ленты через `ComponentManager.ItemExecuted`.
</details>

<details>
<summary><b>ToolsCables</b> — справочник кабелей</summary>

Справочник кабелей — ключевая спецификация категории «Электрические цепи», на строки которой ссылается параметр цепи «Проводник».

- **Справочник кабелей** — находит справочник в модели и показывает его строки и число цепей, где каждая строка уже проставлена.
- **Правка справочника** — окно-таблица: правка значений и добавление новых кабелей (удаление строк запрещено — на них могут ссылаться цепи).
- **Выгрузить справочник** — выгружает справочник в .xlsx.
- **Загрузить справочник** — загружает справочник из .xlsx: строки сопоставляются по ключевому имени, найденные обновляются, новые добавляются.
</details>

<details>
<summary><b>ToolsFamilies</b> — семейства</summary>

- **Загрузить семейства** — загружает выбранные семейства/типоразмеры из папки-каталога .rfa в модель.
- **Обновление/проверка семейств** — показывает актуальность и обновляет семейства модели из каталога.
</details>

<details>
<summary><b>ToolsRooms</b> — помещения</summary>

- **Найти помещение** — поиск, фильтрация по номеру/названию и подсветка помещения (в т.ч. из связей).
- **Запись номера помещения** — переносит значение помещения из связанной модели в параметр выбранных элементов по маске.
- **Двухуровневые лоты** — группирует помещения связи по имени лота и выводит только лоты, чьи помещения стоят на нескольких уровнях (с секцией и списком уровней).
- **Марки помещений** — расставляет и чинит марки помещений из связанной модели (в т.ч. осиротевшие/съехавшие).
- **Диагностика марки** — временная диагностика: показывает, что видит логика «Марок помещений» по выбранной марке. Модель не меняет.
</details>

<details>
<summary><b>ToolsSchedules</b> — спецификации</summary>

- **Экспорт в Эксель** — выгружает активную спецификацию в .xlsx (без openpyxl/Excel).
- **Импорт из Эксель** — загружает правки из .xlsx обратно в модель по столбцу «Revit ID».
- **Разбить спецификацию** — делит спецификацию на листе на участки заданной высоты.
- **Модель → JSON** — выгружает снимок модели (элементы, параметры, уровни, по желанию цепи, координаты, марки, помещения и пространства из связей с контурами, каталог типоразмеров) в .json — например, чтобы отдать на анализ Claude. Shift+клик — что выгружать: область, категории, параметры и т.п.
- **JSON → модель** — загружает правки из снимка обратно в модель: значения параметров, перемещение/поворот элементов и марок, создание новых элементов (раздел `"new"`), с предпросмотром «было → станет» и пометкой конфликтов. Подробнее — `docs/json-snapshot.md`.
</details>

<details>
<summary><b>FilterSelection</b> — фильтр выбора</summary>

- **Фильтр выбора** — выделение элементов на виде, ограниченное отмеченными категориями.
</details>

<details>
<summary><b>Music</b> — управление плеером</summary>
- **Предыдущий трек**, **Пуск/пауза**, **Следующий трек** — медиаклавиши Windows для активного проигрывателя.
- **Тише**, **Громче** — шаг системной громкости Windows.
- **Громче**, **Тише** — шаг системной громкости Windows.
</details>

<details>
<summary><b>Mail</b> — почта</summary>

- **Задачи из почты** — разбирает «Входящие» классического Outlook за N дней с помощью ИИ и сохраняет список задач в Excel; почта только читается. ИИ на выбор: Claude или ChatGPT, через приложение под подпиской (Claude Code / Codex CLI) или по ключу API (Anthropic / OpenAI). Работает без открытого проекта. Shift+клик — настройки (способ подключения ИИ со ссылками на инструкции, модель, период, подпапка, промпт, тестовый режим). Подробнее и инструкции по подключению — [docs/email-tasks.md](docs/email-tasks.md#подключение-ии).
</details>

<details>
<summary><b>Заметки</b> — заметки, вопросы и задачи по проекту</summary>

- **Заметка** — быстро записать замечание, вопрос, задачу или напоминание по текущему проекту; код проекта, вид и выбранные элементы подставляются из модели.
- **Сводка** — все заметки проекта: фильтры, «Выполнено / В работе», ответ на вопрос, правка заметки, переход к виду/листу и к привязанным элементам.
- **Настройка** — подключение к Google Таблице и выбор параметров «Сведений о проекте».

Заметки хранятся в Google Таблице **вашей команды**, которую нужно один раз создать: пошаговая инструкция (таблица, скрипт [`Code.gs`](docs/notes/Code.gs), токен, адрес) — [docs/notes-panel.md](docs/notes-panel.md#подключение-для-новой-команды-или-компании).
</details>

Подробности по отдельным инструментам — в [docs/](docs/) и в `README.md` внутри `lib/` и `tests/`.

## Разработка

Общая библиотека лежит в `lib/` (пакет `lowlife`) и автоматически попадает в `sys.path` pyRevit — см. [lib/README.md](lib/README.md) для справки по модулям. Скрипты кнопок (`script.py`) должны оставаться тонкой оркестрацией поверх `lib/lowlife/`.

Билд-шага, пакетного менеджера и линтера нет; проверка изменений — через загрузку расширения в Revit. Чистая логика без Revit API (графы, адресация, шлейфы, раскладки) покрыта юнит-тестами в [tests/](tests/) — запуск `python -m pytest tests -v` под Python 2.7 + `pytest<5`, подробности в [tests/README.md](tests/README.md). Подробные архитектурные заметки и грабли IronPython/Revit API — в [CLAUDE.md](CLAUDE.md).

## Логотип

Знак — монограмма «⅃Γ» (зеркальная L из «Low» и перевёрнутая оранжевая L из «Life»), название — авторская графика LowLife с той же оранжевой «Γ»; в окне «О программе» название набрано шрифтом. Файлы и генератор — в [`docs/brand/`](docs/brand/) (`python docs/brand/make_brand.py` пересобирает PNG/SVG логотипа, картинку названия и иконку кнопки «О программе»). Иконки всех кнопок — в той же палитре, отдельно для светлой темы Revit (`icon.png`: светлый фон, чёрный рисунок) и для тёмной (`icon.dark.png`: чёрный фон, белый рисунок), с оранжевым акцентом (`docs/brand/restyle_icons.py`).
