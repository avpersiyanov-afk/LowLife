# Общие параметры (ФОП), нужные кнопкам LowLife

Каждая кнопка, которая пишет что-то в параметр элемента модели, узнаёт **имя**
этого параметра не из кода, а из своих настроек (JSON-файл в
`%APPDATA%\pyRevit\...`, заполняется через Shift+клик по кнопке — см.
`scs_settings.py`/`skud_settings.py`/`fire_alarm_settings.py` и т.д. в
`lib/lowlife/`). Сами имена параметров — соглашение конкретного проекта
(обычно общие параметры вида `SMNX_...` из подключённого файла ФОП), поэтому
в трекаемых файлах репозитория они нигде не зашиты (см. `CLAUDE.md`).

Этот файл — обратная сторона того же соглашения: не имена, а **роли**
параметров, которые должны существовать в проекте (как общий параметр,
привязанный к нужным категориям) и быть вписаны в соответствующее поле
настроек, чтобы кнопка могла отработать. Используйте его как чек-лист при
подключении нового проекта/ФОП — рядом впишите для себя, каким реальным
параметром ФОП закрыта каждая строка (эти реальные имена — в
`docs/*.local.md`/`SeedMySettings.pushbutton`, они не коммитятся).

## Как читать таблицы

- **Категории** — к каким категориям Revit параметр должен быть привязан
  (Общие параметры → Управление общими параметрами), иначе кнопка не найдёт
  или не запишет значение.
- **Instance/Type** — привязка к экземпляру или к типу элемента.
- **Тип данных** — `Текст`/`Число` (`Целое число` для служебных счётчиков),
  как в определении общего параметра.
- **Обязателен** — без него кнопка останавливается с сообщением о
  недостающем поле (`require()`/`ensure_binding`) или явно указана
  необязательность в описании поля настроек. Необязательные параметры
  включают дополнительную возможность (например структурную схему) и не
  мешают работать остальным кнопкам той же панели, если их не заполнять.
- **Авто-привязка** — «да», если кнопка `SetupParameters` соответствующей
  панели сама проверяет и добавляет привязку параметра к нужным категориям
  из подключённого файла ФОП (`lib/lowlife/scs_parameters.py`,
  `skud_parameters.py`); «нет» — привязку нужно создать в Revit вручную
  (Управление → Общие параметры).

схемы — выбираются из проекта, не текстовые параметры.

## LOI.panel (FillLOI)

Категория семейства элементов-форм фиксирована в коде («Форма»,
`lowlife.loi_fill.FORM_CATEGORY_NAME`) — не общий параметр и больше не
настройка. В настройках указываются только клонируемые параметры
(`param_names_text`, по одному на строке) — произвольный список: любой
параметр, одноимённо существующий и у «Формы», и у целевого элемента,
переносится как есть; фиксированного набора ролей нет. Плюс — в каких
моделях искать «Формы» (`search_locations`/`search_locations_configured`:
текущий файл и/или конкретные загруженные связи по имени), т.к. «Формы»
обычно лежат в отдельной связанной архитектурной модели.
