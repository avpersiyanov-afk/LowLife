# Списки УГО

Кнопка **Схемы → Списки УГО**, тема **Общее**. Работает в проекте Revit.

1. Создайте в Revit пустую легенду-образец. В ней не должно быть элементов
   узлов и текстовых примечаний; линии оформления допустимы. Образец
   выбирается один раз и нужен только для новых легенд.
2. Откройте кнопку. Таблица показывает все загруженные типы категории
   «Элементы узлов», включая неразмещённые. Подпись по умолчанию —
   `Семейство : Тип`; её можно заменить. «Подпись из имени» возвращает
   исходный текст у выделенных строк.
3. Создайте список. В поле «Системы выбранного списка» перечислите его
   системы через запятую. В столбце «Системы» назначьте системы типам.
   Названия свободные, сравнение точное, с учётом регистра.
4. Дополнительно укажите имена списков в столбце «Списки» либо выделите
   строки и нажмите «Выделенные → в список». Узел входит в список, если
   он назначен напрямую **или** имеет хотя бы одну из систем списка.
   Один тип может входить в несколько систем и списков.
5. Выберите тип текста, масштаб и размеры на бумаге. «Сохранить списки»
   запоминает каталог без создания вида. «Создать / обновить легенду»
   сохраняет каталог и строит выбранный список одной транзакцией.

Создаётся легенда `УГО - <список>`, при конфликте имени — с числовым
суффиксом. Повторный запуск обновляет тот же вид по UniqueId; смена имени
списка обновляет имя вида при следующем построении. Переносы текста
определяются выбранной шириной. Подписи выровнены в одну колонку,
шаг строк увеличивается по фактическому габариту символа и текста.

Каталог, подписи и списки хранятся в модели (DataStorage /
ExtensibleStorage), а не в пользовательском JSON-файле. Общие параметры
не добавляются. В совместной работе действуют обычные права Revit на
изменение реестра, легенды и её элементов. «Отмена» ничего не сохраняет.
Если построение не удалось, транзакция откатывается и редактор снова
открывается с введёнными данными.

## Обновление и ограничения

- Размещаются точечные элементы узлов. Линейные элементы узлов не
  поддерживаются: кнопка укажет соответствующий тип до удаления старых строк.
- Кнопка пересоздаёт только свои зарегистрированные элементы и тексты
  выбранной легенды. Их ручные положения и правки текста заменяются;
  подписи следует редактировать в таблице кнопки. Постороннее оформление
  не удаляется. Если удаление затрагивает зависимые посторонние элементы,
  вся операция откатывается.
- Удалённые типы остаются в таблице с состоянием «Тип удалён». Перед
  построением исключите их из списков и систем либо загрузите заново
  и назначьте новые типы. Кнопка не пропускает такие строки молча.
- Удаление списка оставляет его созданную легенду в проекте, но прекращает
  её обновление. Список с тем же именем будет новым списком.
- Существующие ручные легенды автоматически не связываются с каталогом.
  Для первого построения используется пустой образец. Дубликаты
  управляемых легенд, сделанные вручную, кнопка не обновляет.
- Легенды находятся в штатном разделе «Легенды» Диспетчера проекта.
  Настройка группировки диспетчера остаётся штатной настройкой Revit.

## Проверка в Revit 2024

На копии проекта: создайте образец, добавьте два разных типа узлов,
назначьте одному систему, другому список напрямую, измените подпись.
Постройте легенду; повторно запустите, удалите одну запись из состава и
измените другую. Проверьте отсутствие дублей, сохранение ручной линии,
раскладку длинного текста и большого символа. Закройте и снова откройте
проект: состав и подписи должны сохраниться. Также проверьте «Отмена»,
отсутствующий тип, удалённый вид, линейный тип и отказ прав в общей модели.

Автоматические тесты проверяют чистую логику. Работа WPF и размещение
через Revit API требуют проверки внутри Revit.
