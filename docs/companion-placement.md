# «Расстановка РМ, АМ, МДУ» (SPA.panel/PlaceCompanionDevices)

Живёт на `SPA.panel` (система пожарной автоматики), а не на `SPS.panel`
(пожарная сигнализация) — типичные компаньоны этой кнопки, модули
дистанционного управления (МДУ), относятся к СПА, даже если базовый
объект (например, клапан ДУ) относится к другой дисциплине.

Ставит компаньона рядом с уже стоящим объектом: например, ручной пожарный
извещатель (РМ) у каждой двери эвакуационного выхода, или модуль
дистанционного управления (МДУ) у каждого клапана ДУ. Компаньон ставится
со смещением на фиксированное расстояние, и на него переносятся значения
выбранных параметров базового объекта (адрес, обозначение и т.п.).

Логика — `lib/lowlife/companion_placement.py`; настройки и окно —
`lib/lowlife/companion_placement_settings.py`, хранятся в
`%APPDATA%\pyRevit\LowLifeCompanionPlacement_settings.json`.

## Настройка (Shift+клик)

Один текстовый список произвольных имён пар («РМ у дверей, МДУ у
клапанов»), по образцу категорий структурной схемы СКУД
(`skud_settings.py`): вписал имена, нажал «Обновить список» — под полем
появляется раздел на каждое имя. Раздел не пропадает и не теряет
настройки при временном удалении имени из списка — только на момент
запуска расстановки берутся имена, которые сейчас перечислены в поле.

Для каждой пары:

- **Рядом с чем ставить** — один или несколько типов семейств любой
  категории (двери, оборудование, обобщённые модели...) — это и есть
  «базовые объекты».
- **Что ставим** — один тип семейства-компаньона.
- **Смещение** — вперёд/вбок/вверх, в мм, в МЕСТНЫХ координатах базового
  объекта (по направлению его поворота на плане) — поэтому одно и то же
  смещение «вперёд» остаётся вперёд независимо от того, как объект
  повёрнут.
- **Параметры для переноса** — `Источник=Приёмник, Источник2=Приёмник2`
  (без `=` — имя параметра одинаковое по обе стороны). Обязательно нужен
  хотя бы один — без него защититься от повторной расстановки нечем (см.
  ниже), и повторный запуск наплодит дублей.
- **Группировка по 2-4** (опционально, галочка) — см. раздел ниже.
- **Цепь между компаньоном и базовым объектом** (опционально, галочка) —
  см. раздел ниже.

## Группировка по 2-4 (компаньон на несколько входов)

Иногда рядом стоит несколько базовых объектов, а компаньон — не на один
вход, а сразу на несколько (например, модуль на 4 входа). Галочка
«Группировать по 2-4...» в настройках пары включает это для неё:

- **Компаньон на группу** — отдельный тип семейства (с несколькими
  входами), ставится ОДИН на группу — не путать с обычным «Что ставим»
  (тем самым компаньоном по одному на объект), который используется для
  всех, кто в группу не попал.
- **Радиус группировки, мм** — базовые объекты объединяются в группу по
  2-4, если стоят в одном помещении (`Room` ТЕКУЩЕГО документа в точке
  объекта, `Document.GetRoomAtPoint`) И в пределах этого радиуса друг от
  друга. По умолчанию 2000 мм.
- Объект без определяемого помещения (частый случай для дверей — точка
  вставки лежит в проёме стены, а не внутри контура комнаты) в группу не
  попадает — идёт по обычному, поштучному пути со своим компаньоном.
- Если рядом оказалось больше 4 кандидатов одного помещения — берутся 4
  ближайших друг к другу, из оставшихся собираются следующие группы по
  2-4 (а не одна переполненная группа).
- Точка установки компаньона на группу — центр группы (среднее точек её
  объектов) плюс то же смещение из настроек пары, но приложенное в
  МИРОВЫХ осях X/Y (не в местных координатах одного объекта — общего
  поворота у группы нет).
- Значения параметров: каждый источник из списка «Параметры для
  переноса» берётся у ВСЕХ объектов группы, сортируется и склеивается
  через `", "` в один и тот же приёмник компаньона-на-группу (то есть
  один параметр-приёмник получает сразу все адреса/обозначения группы
  одной строкой, а не по отдельному приёмнику на каждый вход).
- Защита от повторной расстановки — тем же способом, что и у обычных
  компаньонов (см. ниже), но по своим экземплярам компаньона-на-группу и
  по этим склеенным значениям.

## Цепь между компаньоном и базовым объектом

Та же логика, что и у «Цепи изолятор-устройства»
(`lib/lowlife/fire_alarm_isolator_circuits.py`,
`lib/lowlife/electrical_circuits.py`): компаньон играет роль изолятора —
источник/панель цепи (назначается через `ElectricalSystem.SelectPanel`,
с тем же защитным манёвром от Revit-ошибки «Not allow circular
connection...», когда панели пришлось временно попасть в список
элементов цепи), а обслуживаемый(е) им базовый объект — при поштучной
расстановке один, при групповой — все объекты группы — становятся
нагрузкой (`lowlife.companion_placement.build_companion_circuit`).

Включается галочкой «Строить электрическую цепь...» в настройках пары:

- **Тип электрической цепи Revit** — обязателен, если галочка включена;
  выбирается пикером (`ElectricalSystemType`: `Controls`, `FireAlarm`,
  `Data`...), как в «Параметры цепей (общее)».
- **Параметр цепи «Панель»** — опционально; если задан, туда пишется имя
  компаньона (аналог «Панель» = имя изолятора у «Цепи
  изолятор-устройства»).
- Сразу после создания цепи ей проставляется режим траектории Revit «Все
  устройства» (`CircuitPathMode.AllDevices`), чтобы Revit сам посчитал
  `Length` по фактическому положению элементов.
- Цепь строится только для компаньонов, поставленных В ЭТОМ запуске
  кнопки (не для уже существующих) — раз уже стоящий компаньон
  обнаруживается защитой от повторной расстановки и пропускается, для
  него код построения цепи просто не вызывается. Если компаньон был
  поставлен ДО того, как для его пары включили эту галочку, цепь для
  него так и не появится — только для новых.
- Если создание цепи не удалось (например, категория компаньона не
  подходит под источник цепи) — попадает в счётчик «не удалось
  построить», сам компаньон при этом остаётся на месте.

## Как размещается компаньон

- Точка — точка базового объекта (`LocationPoint`, иначе центр
  bounding box) плюс смещение, повёрнутое на угол поворота базового
  объекта.
- Хост — если у базового объекта есть `Host` (например, стена), компаньон
  пробует встать на тот же хост; иначе — по уровню базового объекта
  (или ближайшему снизу, если у объекта уровня нет); в крайнем случае —
  вовсе без привязки. Первое, что примет Revit для семейства компаньона.
- Семейства, требующие размещения на конкретной грани (face-based без
  host-элемента), пока не поддерживаются — такие компаньоны попадут в
  счётчик «не удалось создать».

## Защита от повторной расстановки

Перед созданием компаньона кнопка ищет среди уже существующих экземпляров
компаньона (того же типа) те, что стоят в пределах разумного радиуса от
точки установки, и сравнивает их параметры-приёмники с тем, что перенесётся
с базового объекта сейчас. Если найден компаньон с уже совпадающими
значениями — базовый объект считается уже обработанным и пропускается
(«уже стояло» в отчёте). Поэтому список параметров для переноса — не
только для удобства, а и рабочий механизм защиты от дублей.

## Что обрабатывается за один запуск

Все базовые объекты настроенных типов на активном виде (не только
выделенные) — по каждой настроенной паре отдельно.

## Отчёт

По каждой паре: сколько базовых объектов найдено на виде, сколько
компаньонов поставлено поштучно, сколько уже стояло (пропущено), сколько
без точки расположения и сколько не удалось создать — и, если для пары
включена группировка: сколько групп найдено и сколько компаньонов на
группу поставлено/уже стояло/не удалось создать; и, если включено
построение цепи: сколько цепей построено и сколько не удалось.
