# Обратная связь — кнопка «Обратная связь» на панели LowLife

Кнопка рядом с «О программе». Окно: **Панель** (первая строка — «Общее — LowLife
в целом») → **Кнопка** этой панели (или «Вся панель / не знаю») → **Проблема /
Предложение** → **Описание** и необязательный контакт. Ctrl+Enter — отправить.
Отправить можно только с отмеченной галочкой согласия на обработку персональных
данных: она не запоминается и ставится заново для каждого сообщения, без неё
кнопка «Отправить» недоступна.
К сообщению сами добавляются имя пользователя Revit и Windows, версия LowLife
(коммит), версия Revit и имя файла открытой модели.

Список панелей и кнопок строится по папкам расширения (`lib/lowlife/ribbon_catalog.py`:
подписи из `bundle.yaml`/`__title__`, порядок из `layout:`), так что новые кнопки
появляются в нём сами.

Сообщения уходят в **Google Таблицу автора** — отдельную от «Заметок по проекту».
Веб-приложение (`docs/feedback/Code.gs`) дописывает строки; прочитать чужие
отзывы через него нельзя — только статус и ответ на свои (см. «Ответ автора»
ниже). Без интернета (или
пока адрес не задан) сообщение сохраняется в
`%APPDATA%\pyRevit\LowLifeFeedback\queue.json` и уходит при следующей отправке;
повторная отправка дублей не создаёт (проверка по ID).
Окно не ждёт таблицу: «Отправить» сразу закрывает его, а сообщение уходит
в фоне, пока вы работаете дальше.

Код: `lib/pnotes/feedback.py` (окно и отправка, HTTP — общий с заметками
`pnotes/core.py`), разметка — `lib/pnotes/xaml/feedback.xaml`, кнопка —
`LowLife.tab/_Themes.panel/Feedback.pushbutton`.

## Установка Google-части (один раз, делает автор)

1. Создайте новую Google Таблицу (на своём аккаунте).
2. **Расширения → Apps Script**, вставьте целиком `docs/feedback/Code.gs`, сохраните.
3. Выполните функцию `setup` и выдайте разрешения («приложение не проверено» —
   «Дополнительно → Перейти к проекту»). Появится лист «Обратная связь».
4. **Развернуть → Новое развертывание → Веб-приложение**, запуск от имени «Я»,
   доступ «Все» → скопируйте адрес, который заканчивается на `/exec`.
5. Впишите его в `FEEDBACK_URL` в `lib/pnotes/feedback.py`, закоммитьте — после
   обновления LowLife у всех пользователей сообщения пойдут в таблицу (и
   накопленные локально тоже).

Проверить до коммита: положите себе `%APPDATA%\pyRevit\LowLifeFeedback\config.json`
вида `{"url": "https://script.google.com/macros/s/…/exec"}` — личный адрес
перекрывает `FEEDBACK_URL`.

Адрес попадает в публичный репозиторий, поэтому токена нет (его бы всё равно
было видно). Защита: веб-приложение только дописывает строки, обрезает длинные
поля, экранирует значения, похожие на формулы, и принимает не больше
20 сообщений в минуту. Если начнётся спам — сделайте новое развертывание
(адрес сменится) и обновите `FEEDBACK_URL`.

Письмо на почту о каждом сообщении: `NOTIFY_BY_EMAIL = true` в `Code.gs`
(Google спросит разрешение на отправку почты).

Столбцы «Статус» (список: Новое / В работе / Сделано / Не будет / Дубль),
«Комментарий» и «Ответ пользователю» заполняются вручную; «Комментарий» видит
только автор, а статус и ответ — отправитель (см. ниже).

## Ответ автора

Чтобы ответить, напишите текст в столбец **«Ответ пользователю»** строки сообщения
(и при желании поменяйте «Статус»). Рядом, в «Ответ дан», само ставится время
(простой триггер `onEdit` в `Code.gs`). Исправили ответ — у пользователя он снова
станет новым.

Как ответ доходит до пользователя:

- Каждое отправленное сообщение остаётся у него в
  `%APPDATA%\pyRevit\LowLifeFeedback\sent.json` (последние 100). Сообщения,
  отправленные до этой версии LowLife, там не лежат — на них отвечайте по контакту.
- LowLife спрашивает веб-приложение (действие `replies`) о статусе и ответе по ID
  своих сообщений: в фоне при запуске Revit и при открытии модели (не чаще раза в
  3 часа; заодно досылаются сообщения, не ушедшие без связи), а также при каждом
  открытии окна «Обратная связь» и по кнопке «Проверить ответы».
- В окне — вкладка **«Мои сообщения»**: свои сообщения со статусом и ответом автора;
  при новом ответе окно сразу открывается на ней, а в заголовке вкладки —
  «новых ответов: N».
- Новый ответ, найденный фоновой проверкой, — уведомление Windows «LowLife — ответ
  автора»; непрочитанный ответ напоминает о себе и при открытии модели (один раз за
  сеанс Revit). Прочитанным ответ считается, когда открыта вкладка «Мои сообщения».

ID сообщения — случайные 16 hex-символов, известные только отправителю и вам;
веб-приложение отдаёт статус и ответ только по точному ID (не больше 200 ID в
запросе, 120 запросов в минуту), поэтому чужие ответы так не прочитать.
Поэтому не пишите в ответе того, что не предназначено отправителю, — для этого
есть «Комментарий».

При изменении кода скрипта: **Управление развертываниями → ✏️ → Новая версия**
(новое развертывание даёт новый адрес).

## Статистика запусков кнопок

Тем же веб-приложением LowLife собирает, какие кнопки нажимают: при каждом запуске
кнопки LowLife (с ленты или через «Поиск») записываются время, панель и кнопка,
имена пользователя Revit и Windows, имя файла модели, версии LowLife и Revit.
Содержимое моделей не отправляется.

- Как ловится: `hooks/app-init.py` → `lib/pnotes/usage.py` подписывается на клики по
  ленте (`Autodesk.Windows.ComponentManager.ItemExecuted`); Id кнопки вида
  `CustomCtrl_%CustomCtrl_%LowLife%<панель>%<кнопка>` сопоставляется с
  `ribbon_catalog.list_buttons()` (список «Тема» и прочее не-кнопки не считаются).
  «Поиск» запускает кнопки через `PostCommand` — такой запуск он записывает сам
  (столбец «Откуда» = «Поиск»).
- Клик только дописывает строку в `%APPDATA%\pyRevit\LowLifeUsage\queue.json`, сеть
  не трогает. Отправка — в фоне, пачками: когда накопилось 20 запусков или первому
  больше 30 минут, а также при запуске Revit. Без связи очередь ждёт (не больше
  5000 последних запусков); повтор той же пачки строки не дублирует.
- Выключить: галочка «Отправлять автору статистику запусков» в окне «О программе»
  (действует сразу; выключение заодно стирает неотправленное). Хранится в
  `%APPDATA%\pyRevit\LowLifeUsage\config.json`.
- В таблице: лист «Запуски» (строка на запуск) и «Статистика» — формулы QUERY:
  кнопки за всё время и за последние 30 дней, пользователи (число запусков и
  последний), запуски по месяцам. Листы создаются сами при первой пачке (или
  функцией `setup`). Кнопки, которых нет в статистике, никто не нажимал.
  Формулы подстраиваются под локаль таблицы (в русской аргументы разделяются «;»).
  Лист «Статистика» создаётся только если его нет — чтобы пересоздать его
  (например, после обновления `Code.gs`), удалите лист и выполните `setup`.

**После обновления `Code.gs`** (появились действия `usage` и `replies`) вставьте
новый код в Apps Script и сделайте **Управление развертываниями → ✏️ → Новая
версия** — адрес останется прежним. До этого старое веб-приложение отвечает
«Неизвестное действие»: запуски копятся у пользователей, а ответы не проверяются.
Столбцы «Ответ пользователю» и «Ответ дан» допишутся в лист сами при первом
запросе (или функцией `setup`); порядок прежних столбцов не меняйте — веб-приложение
пишет строки по позициям и откажется работать, если столбец переименован.
