# Переименование выгрузки (RenameExportFiles)

Кнопка `Tools.panel/RenameExportFiles` («Переименование выгрузки»). Логика —
в `lib/lowlife/export_rename.py`, скрипт кнопки тонкий. Зарегистрирована в
теме `General` переключателя `_Themes.panel` (рядом с `ZoomToElement`).

## Зачем

Два листа должны идти под **одним** номером, но с разными именами. Revit и
ModPlus собирают имя файла выгрузки из «номер листа + имя листа», поэтому
одинаковый номер даёт конфликт имён файлов. Обходной приём: дать листам
разные номера — например `0000` и `000` — а после выгрузки привести `0000`
к `000`. Тогда на диске оба файла отличаются только именем листа.

## Что делает за один запуск

`run_after_export`:

1. **Спрашивает папку выгрузки.** Если папка уже использовалась
   (`last_folder` в настройках) — показывает её в диалоге с кнопками
   «Да, эта папка» / «Выбрать другую…» / «Отмена»; «Да» — кнопка по
   умолчанию, подтверждается Enter'ом. Иначе — `forms.pick_folder`.
   Определить папку, куда сложил файлы ModPlus, программно нельзя (плагина
   в среде разработки нет, его конфиг не читаем), поэтому это полуавтомат.
2. **Строит план** (`plan_renames`): в папке (и подпапках, если включено)
   берёт файлы с подходящим расширением (`.dwg`, `.pdf` по умолчанию),
   в имени которых есть `from_token` (`0000`), и заменяет в имени **все**
   вхождения на `to_token` (`000`). Если целевое имя уже занято другим
   файлом — пара помечается `collision` и пропускается.
3. **Показывает список** пар «старое → новое» (первые 12) и, если есть
   коллизии, перечисляет пропускаемые. Просит подтверждение (Yes/No).
4. **Переименовывает** `os.rename`. В модели Revit ничего не меняется —
   транзакция не нужна. По итогу — `forms.toast` со счётчиками.

Обычный клик по кнопке = ровно этот сценарий, запускается вручную сразу
после выгрузки ModPlus.

## Автозапуск: слежение за Проводником

`startup.py` расширения → `export_watcher.install(__revit__)`. Модуль
`lib/lowlife/export_watcher.py` подписывается на `UIApplication.Idling`
(Revit дёргает его в паузах между действиями — тот же механизм, что в
`route_preview.schedule_preview_cleanup`) и не чаще раза в `SCAN_INTERVAL`
(2 с) перечисляет открытые окна Проводника через COM `Shell.Application`.
Появилось **новое** окно на папке, где есть файлы с `from_token` в имени
моложе `FRESH_SECONDS` (30 мин) → `rename_folder_interactive` по этой
папке (тот же диалог, `quiet_if_empty=True` — молча выходит, если менять
нечего).

Расчёт на то, что ModPlus в конце экспорта открывает папку выгрузки в
Проводнике. Осознанные ограничения:

- работает всю сессию Revit; лёгкий COM-поллинг окон;
- сработает на **любом** новом окне Проводника, если там окажутся свежие
  подходящие файлы (фильтр по свежести + «не спрашивать дважды про ту же
  папку», `_handled_dirs`, это почти исключает);
- Проводник с вкладками (Win11): папку, открытую новой **вкладкой** в
  существующем окне, не поймать — только новое окно;
- на этапе разработки не проверяется (нет Revit) — правится по факту.

Отключение: Shift+клик по кнопке → «Следить за открытием папки…: нет»
(ключ `watch_explorer`). Выключение действует сразу (watcher каждый тик
перечитывает настройку), включение — после перезагрузки pyRevit.

## Настройки (Shift+клик)

`EXEC_PARAMS.config_mode` → `export_rename.configure()`: слежение за
Проводником (`watch_explorer`), `from_token` / `to_token`, расширения,
обход подпапок, автозапуск по команде и подстроки идентификатора
команды-триггера. Хранятся простым JSON в
`%APPDATA%\pyRevit\LowLifeExportRename_settings.json` (тот же подход, что
`scs_settings.py`, а не `pyrevit.script.get_config()`).

## Автозапуск по команде — TODO

Точнее слежения за Проводником был бы pyRevit-хук на завершение команды
ModPlus «Экспорт». Первый заход — хук `hooks/command-after-exec.py`
**без** `[command_id]` в имени файла (расчёт на срабатывание после любой
команды) — **эта сборка pyRevit такой хук не регистрирует**:
`Failed registering hook script command-after-exec.py | Адресат вызова
создал исключение`. Файл удалён.

Рабочий вариант — хук с точным идентификатором команды в имени:
`hooks/command-after-exec[<command-id>].py`, тело из трёх строк:

```python
from pyrevit import EXEC_PARAMS
from lowlife import export_rename
try:
    cid = unicode(EXEC_PARAMS.event_args.CommandId.Name)
except Exception:
    cid = u""
export_rename.run_after_export(command_id_text=cid)
```

Нужен `<command-id>` команды экспорта ModPlus. Как достать — запустить
ModPlus «Экспорт» один раз и посмотреть журнал Revit
(`%LOCALAPPDATA%\Autodesk\Revit\Autodesk Revit <версия>\Journals\journal.*.txt`,
самый свежий), строка вида:

```
Jrn.RibbonEvent "Execute external command:CustomCtrl_%CustomCtrl_%ModPlus%mprExport…:…"
```

Идентификатор — токен `CustomCtrl_%CustomCtrl_%ModPlus%…` из этой строки.
`command_matches` в модуле уже готов сопоставлять по подстроке
(`trigger_substrings`), так что в имя файла хука можно поставить точный id,
а фильтр оставить как есть.

У пользователя журналы Revit на месте не создаются (2026-09-09) —
поэтому этот путь пока отложен, работает слежение за Проводником выше.
