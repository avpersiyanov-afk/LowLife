# Переименование выгрузки (RenameExportFiles)

Кнопка `Tools.panel/RenameExportFiles` («Переименование выгрузки»). Логика —
в `lib/lowlife/export_rename.py`, скрипт кнопки тонкий. Зарегистрирована в
теме `General` переключателя `_Themes.panel` (рядом с `ZoomToElement`).

## Зачем

Два листа должны идти под **одним** номером, но с разными именами. Revit и
ModPlus собирают имя файла выгрузки из «номер листа + имя листа», поэтому
одинаковый номер даёт конфликт имён файлов. Обходной приём: дать листам
разные номера — например `0000` и `000` — а после выгрузки привести `0000`
к `000`. Тогда на диске оба файла отличаются только именем листа.

## Что делает за один запуск

`run_after_export`:

1. **Спрашивает папку выгрузки.** Если папка уже использовалась
   (`last_folder` в настройках) — показывает её в диалоге с кнопками
   «Да, эта папка» / «Выбрать другую…» / «Отмена»; «Да» — кнопка по
   умолчанию, подтверждается Enter'ом. Иначе — `forms.pick_folder`.
   Определить папку, куда сложил файлы ModPlus, программно нельзя (плагина
   в среде разработки нет, его конфиг не читаем), поэтому это полуавтомат.
2. **Строит план** (`plan_renames`): в папке (и подпапках, если включено)
   берёт файлы с подходящим расширением (`.dwg`, `.pdf` по умолчанию),
   в имени которых есть `from_token` (`0000`), и заменяет в имени **все**
   вхождения на `to_token` (`000`). Если целевое имя уже занято другим
   файлом — пара помечается `collision` и пропускается.
3. **Показывает список** пар «старое → новое» (первые 12) и, если есть
   коллизии, перечисляет пропускаемые. Просит подтверждение (Yes/No).
4. **Переименовывает** `os.rename`. В модели Revit ничего не меняется —
   транзакция не нужна. По итогу — `forms.toast` со счётчиками.

Обычный клик по кнопке = ровно этот сценарий, запускается вручную сразу
после выгрузки ModPlus.

## Автозапуск

`export_watcher.install()` вызывается из `startup.py`, `hooks/doc-opened.py`
и из скриптов кнопок (`ensure_installed()` — на случай, если первые два в
этой сборке pyRevit не отработали). Дубли отсекает процесс-глобальный
словарь в `sys` (переживает перезагрузку движка pyRevit, но не перезапуск
Revit).

**Триггер — `Autodesk.Windows.ComponentManager.ItemExecuted`**
(`clr.AddReference("AdWindows")`). Клик по кнопке ленты, чьи
`Id`/`Text`/`Cookie` подходят под `trigger_substrings` (по умолчанию
`mprSheetExport` — «Экспорт листов» ModPlus, id
`CustomCtrl_%CustomCtrl_%ModPlus%Экспорт и Импорт%mprSheetExport`; нужен
`enabled`) — **сразу же**, ещё до открытия модального окна экспорта,
запускает фоновый STA-поток `_poll_and_rename`.

**Фоновый поток `_poll_and_rename`** (вне UI-потока Revit — на сетевой
шаре это секунды, на UI-потоке подвешивало Revit):

- раз в `POLL_INTERVAL` (2 с) смотрит подпапки `export_root` и/или папки
  рядом с `last_folder` (`_bases_to_watch`), ищет **новую** подпапку,
  созданную после клика (`_newest_subdir_since`, только `listdir`+`stat`);
- как нашёл — ждёт «стабилизации»: `_folder_sig` (mtime + число подходящих
  файлов в папке и подпапках 1-го уровня) не меняется `STABLE_CYCLES` (3)
  подряд И прошло ≥ `MIN_SETTLE` (8 с) с появления папки = ModPlus дописал;
- затем `plan_renames` → WinForms `MessageBox` да/нет → `apply_renames` →
  итоговый `MessageBox`. `MessageBox`/`FolderBrowserDialog` работают из
  фонового потока, Revit не блокируют;
- если за `ARM_WINDOW` (15 мин) новой папки так и нет — спрашивает папку
  (`FolderBrowserDialog`).

Поиск идёт **параллельно** самому экспорту, поэтому окно о переименовании
появляется через несколько секунд после того, как ModPlus дописал файлы.

`Idling`-подписка осталась только для снятия зависшего флага
(`WORKER_STUCK_AFTER` = 10 мин); логику переименования она не трогает.

Ограничения:

- если ModPlus между файлами делает паузу дольше `STABLE_CYCLES`×`POLL`
  (6 с), поток может решить, что экспорт закончился, раньше времени;
- на этапе разработки не проверяется (нет Revit) — только симуляция
  чистой логики.

Отключение: Shift+клик по кнопке → «Сам замечать завершение экспорта…:
нет» (ключ `watch_explorer`). Аварийно: пустой файл
`%APPDATA%\pyRevit\LowLifeExportRename_OFF` — `install` тогда ничего не
делает (нужен перезапуск Revit, чтобы снять уже висящие подписки).

## Настройки (Shift+клик)

`EXEC_PARAMS.config_mode` → `export_rename.configure()`: авто-режим
(`watch_explorer`), взвод по клику (`enabled`), подстроки для опознания
кнопки экспорта (`trigger_substrings`), `from_token` / `to_token`,
расширения, **корень выгрузки ModPlus (`export_root`)**, обход подпапок.
Хранятся простым JSON в
`%APPDATA%\pyRevit\LowLifeExportRename_settings.json` (тот же подход, что
`scs_settings.py`, а не `pyrevit.script.get_config()`).

## Диагностическая кнопка «Поймать id команды»

`Tools.panel/CaptureExportCommand`, `lib/lowlife/command_probe.py`. Обычный
клик подписывается на `ComponentManager.ItemExecuted` и пишет
`Id`/`Text`/`Cookie` каждой нажатой кнопки ленты в
`%APPDATA%\pyRevit\LowLifeExportRename_commands.log` после строки-маркера;
Shift+клик показывает пойманное после последнего маркера. Ей и добыт id
«Экспорта листов» (журналы Revit у пользователя не пишутся). Оставлена в
расширении на случай, если понадобится опознать другую кнопку.

## pyRevit-хук по команде — почему не он

Первый заход — `hooks/command-after-exec.py` **без** `[command_id]` в имени
(расчёт на срабатывание после любой команды) — **эта сборка pyRevit такой
хук не регистрирует**: `Failed registering hook script
command-after-exec.py | Адресат вызова создал исключение`. Форма с точным
id в имени — `hooks/command-after-exec[<id>].py` — возможно и сработала бы,
но id «Экспорта листов» содержит `%`, пробелы и кириллицу
(`CustomCtrl_%CustomCtrl_%ModPlus%Экспорт и Импорт%mprSheetExport`), такое
имя файла — риск. `ItemExecuted` из `startup.py` (см. выше) проще и уже
проверен диагностической кнопкой.
