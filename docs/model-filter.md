# Фильтр наборов и связей

Кнопка на панели «Инструменты», тема «Общее». После первой установки перезапустите Revit:
закрепляемые панели регистрируются при загрузке расширения.

## Видимость на видах

Два независимых раздела: пользовательские рабочие наборы текущей модели и экземпляры связей Revit.
Галочка показывает группу, снятая — скрывает; серый квадрат означает смешанное состояние.
Для наборов изменяется переопределение видимости на виде, для связей — индивидуальное скрытие
экземпляров. Закрытые наборы, незагруженные связи и наборы под управлением шаблона недоступны;
причина показана в подсказке строки. В модели без совместной работы доступны связи.

Поиск находит группы и полные имена, в том числе при неверной раскладке клавиатуры.
Ctrl+клик добавляет группу к выделению, Shift+клик выбирает диапазон.
В «Настройках» или по Shift+клику на кнопке задаются отдельные маски наборов и связей:
`*` — любой текст, `?` — символ, `{часть}` — часть имени для группировки.
Например, `{корпус}_*` объединит имена одного корпуса.

Пресеты сохраняют маски и видимость отдельно для каждой модели. Одноимённые группы наборов
и связей сохраняются независимо. «На виды…» переносит текущие настройки на выбранные виды.
Категории, шаблоны и обрезка могут дополнительно ограничивать видимость. Панель не открывает
рабочие наборы и не перезагружает связанные документы.

## Управление рабочими наборами

«Управление наборами…» открывает редактор правил для текущего проекта с совместной работой.
Это операции над всем проектом, в отличие от галочек видимости.

1. Добавьте правило вручную, выберите наборы через «Из текущей модели…» или добавьте имена
   наборов загруженных связанных моделей через «Из связей…».
2. Укажите действие, источник и назначение:
   - **Создать** — создаёт недостающий пользовательский набор; существующий пропускается.
   - **Переименовать** — меняет имя существующего набора. Занятое имя назначения блокирует
     переименование; для объединения используйте перенос.
   - **Перенести элементы** — переносит экземпляры из исходного набора в указанный,
     создавая набор назначения при необходимости. Исходный набор остаётся.
3. Нажмите «Предварительный просмотр…». План показывает конкретные имена и количество
   переносимых элементов. «Применить к проекту» выполняет весь план одной транзакцией;
   ошибка назначения или сохранения приводит к откату.

Правила выполняются сверху вниз. Источник использует ту же маску полного имени.
В назначении `{1}` заменяется полным исходным именем, `{2}` — первой захваченной частью
маски. Например, источник `Old_{часть}`, назначение `New_{2}`.
Закрытые наборы, недопустимые имена, конфликты и недоступные для переноса элементы
блокируют применение с объяснением. При изменении модели между просмотром и применением
нужно заново просмотреть план. Поиск в редакторе скрывает строки, но не исключает их из плана.

«Сохранить правила» сохраняет конфигурацию без изменения модели. «Выгрузить настройки…» /
«Загрузить настройки…» переносят правила JSON между проектами. Файл содержит ключ
`workset_rules` со списком объектов `action` (`create`, `rename`, `map`), `source`, `target`.
Данные кнопки хранятся в `%APPDATA%\pyRevit\LowLifeModelFilter_settings.json`.

## Ручная проверка в Revit

- Сравнить галочки с В/Г на плане и 3D; проверить наследование глобальной видимости наборов.
- Проверить закрытый набор, незагруженную связь и управление набором шаблоном.
- Проверить одинаковые имена в обоих разделах, маски, поиск, Ctrl/Shift, пресеты и «На виды…».
- После смены вида/документа и Undo убедиться, что панель обновляется и не меняет другой вид.
- В тестовой модели создать и переименовать набор, перенести элементы, проверить Undo.
- Проверить конфликт имён, закрытый набор и элемент без доступа на запись: частичных правок нет.
- Проверить цепочку переносов A → B → C, создание по связи и перенос правил JSON.

Автоматические тесты проверяют планирование, текущие состояния и откат через заменители API.
Они не проверяют работу WPF, регистрацию панели и реальную модель Revit.
