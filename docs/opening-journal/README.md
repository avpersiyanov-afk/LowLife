# Google-журнал заданий LowLife

Администратор настройки в Revit: Windows-пользователь **persiyanov**.
Его имя зафиксировано в коде; URL и токены в репозитории отсутствуют.
Остальным пользователям доступна **«Открыть таблицу»**, без настройки подключения.
Журнал отправляется автоматически после выдачи, перевыдачи, отзыва,
решения КР/АР и подтверждения ВИС. Отдельной кнопки публикации нет.
Выдавать и отзывать токены может только Google-администратор через меню таблицы.

## Первое подключение администратором

1. Под своим Google-аккаунтом создайте пустую Google-таблицу.
2. Откройте **Расширения → Apps Script**, замените код файлом [Code.gs](Code.gs).
   Используйте движок V8 (стандартный для новых проектов).
3. Запустите функцию setupJournal, разрешите доступ скрипту. Будут сохранены ID таблицы
   и Google-email администратора. Обновите страницу таблицы: появится меню **LowLife**.
4. В Apps Script выберите **Развернуть → Новое развёртывание → Веб-приложение**:
   выполнять от вашего имени, доступ **«Все»**. Скопируйте адрес с окончанием /exec.
   Запросы без действительного токена скрипт отклоняет; публичное развёртывание
   само по себе не предоставляет доступ к данным таблицы.
5. В Revit откройте ВИС/КР/АР: шифр читается из «Сведений о проекте», как в «Заметках». Под Windows-логином
   persiyanov появится **«Подключение таблицы»**. В окне показаны код проекта,
   роль и ID текущей модели; текст можно выделить и скопировать.
6. В Google-таблице выберите **LowLife → Выдать токен группы**. Укажите название
   группы (например ОВ, ВК, КР) и роль VIS, KR или AR. Код объекта и ID модели для токена не нужны.
   Скопируйте токен и его ID для возможного отзыва. Токен показывается один раз.
7. В окне Revit введите URL и токен → **«Проверить и сохранить»**.
   Под полями есть серые пояснения, а кнопка **«Инструкция подключения Google»** открывает эту страницу.
   Проверяется роль. Подключение группы сохраняется сразу для всех объектов и моделей этой роли в вашем профиле.
8. Выдайте задание через интерфейс ВИС. После фиксации транзакции оно
   автоматически попадёт в локальную очередь и отправится в Google в фоне.
   Отправка и повторы выполняются без уведомлений. Сохраните/синхронизируйте RVT для обмена связями.

Новый токен группы действует **на всех объектах и моделях одной роли**
в этом Google-журнале. Его достаточно выдать группе один раз. На каждом
компьютере/Windows-профиле подключение устанавливается один раз для этой роли.
Для ВИС, КР и АР используются соответствующие роли: токен VIS не принимает
решения от имени KR или AR. Старые токены объектов/моделей остаются
совместимыми и сохраняют прежние ограничения. Для перехода на общий доступ
один раз выдайте новый токен группы после обновления Code.gs и развёртывания.

## Подключение инженеров

Настройку инженеру устанавливают один раз, **в его Windows-сеансе**:

- запустите [Install-Connection.ps1](Install-Connection.ps1) в Windows PowerShell;
- введите роль, URL и общий токен группы; код объекта и ID модели не требуются;
- скрипт проверит права и сохранит токен через Windows DPAPI CurrentUser.

Скрипт установки читает токен скрытым вводом: не передавайте токены аргументами
командной строки, сообщениями в общем чате или файлами внутри репозитория.

Подключение хранится в профиле пользователя:
%APPDATA%/pyRevit/LowLifeOpeningJournal_connections.json.
Это отдельный файл, вне модели, общих настроек параметров и экспорта настроек
кнопок. Не копируйте его между Windows-профилями: DPAPI не расшифрует чужой токен.

## Вкладки объектов и доступ по ссылке

**Объект определяется кодом проекта** из настроек Revit. Для каждого кода
автоматически создаётся вкладка «Объект …». Все модели ВИС/КР/АР одного объекта
используют один шифр из «Сведений о проекте». Имя вкладки очищается от недопустимых символов и имеет
короткий уникальный суффикс, чтобы похожие названия объектов не смешивались.

На вкладке находятся строки текущего состояния и история: каждая выдача,
перевыдача, отзыв, решение и подтверждение — отдельная строка с датой,
автором и ревизией. Перевыдача не стирает предыдущий выпуск. Столбец «Запись»
позволяет отфильтровать текущее состояние либо события.

Для просмотра по ссылке в Google выберите **Настройки доступа → Общий доступ →
Все, у кого есть ссылка → Читатель**. Можно отправлять ссылку прямо на вкладку.
Токен для просмотра в браузере не требуется; токены нужны для записи из Revit.
Скрипт не меняет общий доступ автоматически.

**Ссылка на вкладку не ограничивает просмотр одной вкладкой.** Читатель
получает доступ ко всему файлу, включая остальные объекты и служебные листы.
Если проектам нужны разные права просмотра, создавайте отдельные Google-файлы
с отдельными развёртываниями скрипта.

## Что находится в таблице

| Лист | Содержание |
|---|---|
| ГИП | Краткий контроль по объекту, дисциплине и получателю: выдачи, принятие, замечания, авторы решений, дата полного принятия |
| Обзор | Общая строка задания: выданная и отвеченная ревизии, результат, замечание, что делать и даты публикаций обеих моделей |
| Задания | Проект, дисциплина, получатель, GUID и номер задания, UID исходного элемента и бокса, модели, конструкция, координаты, размеры, оси, выпуск, ревизия, даты и автор, подтверждение ВИС |
| Ответы КР АР | Решение и замечание, принятая ревизия, дата и автор, GUID/UID проёма, состав объединённого отверстия, геометрия |
| Контроль в Revit | Уровень, статус бокса/проёма, сравнение размеров, смещение, замечание и следующее действие по загруженной связи |
| История | Выдачи, отзывы, решения КР/АР и подтверждения ВИС |
| Публикации | Отдельная дата отправки в Google, версия публикации, модель, группа, пользователи Revit/Windows, контрольная сумма и ссылка на снимок |
| Снимки JSON | Полные JSON-снимки со всеми полями реестра выбранного проекта, разделённые на части |

Дата **выдачи** берётся из Revit, дата **публикации в Google** фиксируется сервером.
Публикация не выдаёт черновики, не принимает задания и не меняет модель.
Неизменённый снимок не создаёт повторную публикацию. Старые версии сохраняются
в журнале публикаций и JSON-снимках; актуальные представления строятся из
последней публикации каждой модели и роли. Исчезновение записи не считается
отзывом: отзывайте задания явной командой в Revit.

Большие значения в обзорных ячейках сокращаются с пометкой; в JSON сохраняются
полностью. Лимит одного снимка — 1,5 млн символов. Если он превышен, публикация
отклоняется без изменения журнала. По мере роста бюро следует архивировать
журнал: квоты Apps Script и лимит числа ячеек Google Sheets сохраняются.
Служебные листы не удаляйте и не редактируйте. Обычные представления можно
перестроить через **LowLife → Восстановить представления журнала**.

## Как работать каждый день

1. ВИС нажимает «Выдать задания ВИС-КР» или «Выдать задания ВИС-АР».
   Выпуск фиксируется в модели и автоматически отправляется в журнал.
   Перевыдача и отзыв отправляются так же; отмена диалога не создаёт событие.
2. КР/АР обновляет связь ВИС и принимает задания, оставляет замечания
   или отрабатывает отзыв. Изменённые решения автоматически отправляются в Google.
3. ВИС обновляет связь получателя и нажимает «Обновить обмен».
   Подтверждение результата также отправляется автоматически.
4. Кнопка **«Открыть таблицу»** открывает общий журнал в браузере.
   Руководитель использует вкладку объекта и фильтры событий.

Запись в Google начинается сразу после фиксации операции в Revit, без ожидания
сохранения RVT на диск. Поэтому **сохранение/синхронизация моделей и обновление
RVT-связей всё равно обязательны**: у смежника иначе останется прежняя геометрия.
Google не меняет модели и не создаёт проёмы. Изменения трассы требуют повторной
расстановки боксов.

Перед отправкой каждый изменённый снимок сохраняется в профиле Windows в
LowLifeOpeningJournal_pending.json, без токенов. При сбое сети или отсутствии
подключения выдача в Revit остаётся выполненной. Повторные попытки выполняются
в фоне раз в минуту без окон, сообщений и изменения текста интерфейса.
Для повтора не нужно открывать окно, нажимать кнопку или менять задание.
После запуска/перезагрузки pyRevit или открытия модели отправка возобновляется
автоматически. При закрытом Revit отправка невозможна и продолжается при следующем запуске. Очередь хранит **все** последовательные выпуски;
более поздняя ревизия одной модели не обгоняет неотправленную предыдущую.
Фоновая отправка продолжает работать после закрытия окна до завершения процесса
Revit. Неотправленные данные сохраняются для следующего запуска.

Отменённая операция и неизменившийся реестр не создают публикацию.
При потере ответа после успешной отправки сервер распознаёт повтор по снимку,
даже если позже уже опубликована другая ревизия.
Для старой восстановленной копии модели запрещено понижать ревизии, терять
задания и сокращать историю. При конфликте откройте актуальную модель и
обратитесь к администратору; не очищайте журнал для обхода проверки.

## Доступ и безопасность

- Обычным инженерам выдавайте **просмотр** Google-таблицы. Не давайте им доступ
  редактора к самой таблице/Apps Script: редактор привязанного скрипта может
  изменить серверный код. Для обсуждений можно предоставить комментирование.
- Только Google-администратор меняет подключение и выдаёт/отзывает токены.
  Windows-логин persiyanov управляет видимостью настройки в Revit; это удобство
  интерфейса. Реальные права проверяются сервером по токену.
- Новый общий токен ограничен ролью VIS/KR/AR, а не объектом, моделью
  или человеком. Название группы — метка в журнале; например, группы ОВ и ВК
  с ролью VIS имеют одинаковые технические права во всех объектах этого журнала.
  Токен не позволяет выдавать другие токены или менять серверные настройки.
- В записях отдельно сохраняются пользователь Revit, Windows-логин (с доменом,
  если он есть) и ID модели. Имена фиксируются при выполнении действия и
  остаются теми же при фоновой отправке, даже если позже работает другой
  сотрудник. В «Публикациях» отдельно показаны группа и отправитель снимка.
- Имена берутся из Revit/Windows. Это сведения об авторе действия, а не
  подтверждённая персональная Google-авторизация. Google технически выполняет
  запись от владельца Apps Script.
- В Script Properties хранятся SHA-256 токенов, на компьютере — шифротекст DPAPI.
  Пользователь всё равно технически может получить собственный токен внутри
  своего Windows-сеанса. Скрытая настройка не является защитой от владельца ПК.
- Для отзыва используйте ID токена в меню LowLife. При утечке отзовите его и
  выдайте новый. Не публикуйте Script Properties, токены или локальные подключения.

## Что проверено

Автономно проверяются сборка снимков, ограничения области доступа,
повторные публикации, конфликт версий, откаты ревизий, разделение ролей,
сохранение длинного JSON и защита от формул в ячейках.
Тесты серверной логики выполняются в Node с моделью API таблицы.
Реальные разрешения Google, перенаправления веб-приложения, DPAPI/PowerShell
и запуск pyRevit должны быть проверены при первом подключении.


## Краткий журнал ГИПа

Вкладка **«ГИП»** обновляется автоматически после каждой доставленной выдачи,
перевыдачи и решения. Одна строка — объект + часть объекта + дисциплина ВИС + получатель КР/АР,
даже если у дисциплины несколько моделей.

В строке показаны даты первой и последней выдачи, последнего принятия,
последнего замечания и последнего решения; авторы решения и замечания;
короткий текст последнего замечания. Счётчики показывают действующие задания,
принятые актуальные ревизии, требующие рассмотрения, замечания, проёмы,
требующие проверки, и неотработанные отзывы. Счётчики относятся к заданиям:
один объединённый проём может закрывать несколько заданий.

**«Все отверстия приняты»** и дата завершения появляются только когда приняты
актуальные ревизии всех действующих заданий, проёмы проверены при публикации
получателя и нет неотработанных отзывов. Дата — самое позднее принятие из
этой группы. Новая выдача/перевыдача снова открывает рассмотрение и очищает
дату завершения. Если все задания отозваны, выводится «Нет действующих заданий»,
а не «Все приняты».

Историческая дата замечания сохраняется после его устранения; количество
замечаний показывает только отклонения актуальных ревизий. Даты публикаций
обеих сторон позволяют оценить свежесть данных. Сводка показывает последние
опубликованные состояния, без предположений о ещё не отправленных решениях.


## НЧ/ПЧ, корпуса и секции

В Google заполняется отдельный лист **«Части объектов»**:

| Шифр объекта | Часть (НЧ/ПЧ) | Корпус/секция | Использовать |
|---|---|---|---|
| ПРОЕКТ-001 | НЧ | 1 | TRUE |
| ПРОЕКТ-001 | НЧ | 2 | TRUE |
| ПРОЕКТ-001 | ПЧ | 1 | TRUE |
| ПРОЕКТ-002 | НЧ | | TRUE |
| ПРОЕКТ-002 | ПЧ | | TRUE |

Интерфейс первого объекта предложит «НЧ-1», «НЧ-2», «ПЧ-1»,
второго — «НЧ» и «ПЧ». Для номера с ведущим нулём, например 01,
задайте столбцу «Корпус/секция» формат обычного текста перед вводом.
Столбец «Использовать»: TRUE, «да», 1 или пусто — использовать;
FALSE или «нет» — не предлагать. Строки других шифров и повторы не смешиваются.
Обычным инженерам по-прежнему достаточно просмотра файла; справочник заполняет
его владелец. Не редактируйте эту таблицу через серверные представления:
лист справочника сохраняется при восстановлении журнала.

Шифр в Revit не вводится вручную в настройках отверстий. Используется
сохранённый параметр шифра из «Заметок»: тот же способ чтения пользовательского
параметра и встроенных ссылок вида [PROJECT_NUMBER]. Читается локальная
сохранённая настройка, без сетевого ожидания. В настройках отверстий можно
явно указать другой параметр «Сведений о проекте»; его имя не зашито в код.
Если параметр в «Заметках» не настроен либо выбран ключ по имени файла,
используется стандартный «Номер проекта». Пустой выбранный параметр
не подменяется вручную сохранённым старым кодом: сначала заполните его в модели.

В верхней части интерфейса видны шифр и список частей. Список загружается
из Google в фоне, последний успешный список сохраняется локально.
Команда **«Обновить части объекта»** перечитывает изменения справочника.
При недоступной сети можно выбрать уже загруженный вариант; выдумать новый
номер вручную нельзя. Неподключённой группе нужно сначала выдать токен для
роли и установить подключение один раз в профиле пользователя. Шифр объекта
по-прежнему читается из модели, чтобы выбирать справочник и вкладку журнала.

Выбранная часть запоминается отдельно для каждой модели и роли. Она нужна
при расстановке и выдаче; переключение выбора не меняет существующие задания.
В таблице окна есть столбец и фильтр частей. Часть сохраняется в JSON бокса,
выданном снимке, решении КР/АР и Google-журнале. На вкладке «ГИП» каждая часть
контролируется отдельно, чтобы завершённая ПЧ не скрывала незавершённую НЧ.

Часть уже выданного задания менять нельзя. Для ошибочной привязки отзовите
задание и создайте отдельное. Старым заданиям без части можно явно назначить
часть: выберите её в интерфейсе, выберите старые боксы и подтвердите перевыдачу.
Это создаст новую ревизию, сохранит старый выпуск и потребует нового принятия.
Задания разных частей нельзя объединять в один проём. Нельзя переименовывать
использованные значения справочника задним числом: добавляйте новую строку,
а старую при необходимости отключайте.
