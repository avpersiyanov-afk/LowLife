# Снимок модели в JSON — «Модель → JSON» / «JSON → модель»

Две кнопки на панели `ToolsSchedules` («Спецификации»), тема `General`
(«Общее») переключателя `_Themes.panel`. Логика — `lib/lowlife/json_snapshot.py`,
настройки — `lib/lowlife/json_snapshot_settings.py`.

Идея: выгрузить нужную часть модели в JSON, отдать файл на анализ (например,
Claude — в том числе в облачной сессии, у которой нет доступа к Revit),
получить исправленный файл и загрузить правки обратно. Модель меняется
**только** кнопкой загрузки — после предпросмотра и одной транзакцией.

## Сценарий

1. **Shift+клик** по «Модель → JSON» — настроить, что выгружать (см. ниже).
   Без настройки выгружаются все элементы активного вида со всеми
   параметрами.
2. **Клик** по «Модель → JSON» → выбрать, куда сохранить `.json`.
3. Отдать файл Claude с задачей, например: «найди устройства СПА без адреса»,
   «пронумеруй адреса по этажам», «заполни пустые параметры LOI по ТЗ».
   Правила формата записаны в сам файл (поле `"readme"`), отдельно объяснять
   их не нужно.
4. **Клик** по «JSON → модель» → выбрать исправленный файл → в списке
   «было → станет» оставить отмеченным то, что записать → «Записать
   отмеченные». Всё пишется одной транзакцией: Ctrl+Z отменяет загрузку
   целиком.

## Настройки выгрузки (Shift+клик)

| Настройка | Что делает |
|---|---|
| **Какие элементы** | Активный вид (план/3D/спецификация) · выделенные элементы · весь документ |
| **Категории** | Имена категорий по одной на строке, кнопка «Выбрать из модели…». Пусто — все категории модели (без аннотаций, осей, уровней, видов) |
| **Параметры** | Имена параметров по одному на строке, кнопка «Выбрать из модели…» (✎ — параметр записываемый). Пусто — все параметры экземпляра |
| Параметры только для чтения | Длины, вычисляемые значения, ссылки — в `"readonly"`, для анализа. По умолчанию вкл. |
| Параметры типа | В `"type_params"`, для анализа. По умолчанию выкл. |
| Пустые значения | Выгружать и незаполненные параметры — включите, если в снимке нужно **заполнять** пустые параметры. По умолчанию выкл. |
| Электрические цепи | Добавляет цепи, куда входят выгружаемые элементы, с панелью и составом цепи. По умолчанию вкл. |
| Координаты и поворот | Точка вставки и поворот / начало-конец линейного элемента, мм — **можно править** (см. «Перемещение»). По умолчанию выкл. |
| Марки | Марки выгружаемых элементов (на активном виде или на всех видах) — положение головы **можно править**. По умолчанию выкл. |

Настройки можно выгрузить/загрузить файлом (кнопки внизу окна), как и у
остальных кнопок.

## Формат файла (version 1)

```json
{
  "format": "lowlife-snapshot",
  "version": 1,
  "readme": ["…правила…"],
  "document": {"title": "…", "path": "…"},
  "exported_at": "2026-09-29 12:00:00",
  "settings": {"scope": "view", "view": "…", "categories": [], "param_filter": null, "…": "…"},
  "elements": [
    {
      "id": 123456,
      "uid": "5a1c…-0001e240",
      "category": "Пожарная сигнализация",
      "family": "…",
      "type": "…",
      "level": "Этаж 01",
      "params":      {"Комментарии": "…"},
      "readonly":    {"…": "…"},
      "type_params": {"…": "…"},
      "circuit":     {"panel": "<uid>", "elements": ["<uid>", "…"]},
      "location":    {"point_mm": [1000.0, 2000.0, 0.0], "rotation_deg": 90.0},
      "h": {"Комментарии": "3f2a9c01", "@location": "a41c07e2"}
    }
  ]
}
```

- **Загружаются обратно `"params"` и `"location"`.** В `"params"` можно
  менять значения и добавлять ключи (имена существующих параметров экземпляра
  этого элемента). Удалённый ключ ничего не меняет.
- Значения — текст как в Revit: числа в единицах проекта, «Да/Нет» —
  `"Да"`/`"Нет"` (понимаются и `true`/`false`, `1`/`0`). Пустая строка
  очищает текстовый параметр; числовой пустой строкой не очистить.
- `"readonly"`, `"type_params"`, `"circuit"`, `"tag"`, `"level"` и прочее —
  только для анализа, их правки игнорируются. Параметры типа намеренно не
  загружаются: изменение меняло бы все экземпляры типа.
- `"uid"`/`"id"` — связь с элементом (сначала UniqueId, запасной — Id).
- `"h"` — отпечатки значений `"params"` на момент выгрузки, по параметру
  (положение — под ключом `"@location"`).
  По ним загрузка различает:
  - значение в файле не правили → не пишется, даже если в модели оно с тех
    пор изменилось (иначе загрузка откатила бы чужую работу);
  - правили в файле, а в модели осталось как было → обычная правка;
  - правили в файле **и** изменили в модели после выгрузки → конфликт: ⚠ в
    списке, по умолчанию **не отмечено**. Добавленный в `"params"` параметр
    считается изначально пустым — если в модели он уже заполнен, это тоже
    конфликт.
- Элементы не создаются и не удаляются: элемент из файла, которого нет в
  модели, попадает в отчёт.

## Перемещение (`"location"`)

Координаты — в мм, в системе координат проекта (внутреннее начало Revit),
та же, что при выгрузке.

| Ключ | У кого | Что делает изменение |
|---|---|---|
| `point_mm` `[x, y, z]` | точечные элементы (оборудование, устройства, помещения) | перемещает элемент в эту точку |
| `rotation_deg` | точечные элементы с поворотом | поворачивает вокруг вертикали до этого угла (абсолютное значение, градусы) |
| `start_mm`, `end_mm` | прямые линейные элементы (лотки, линии, трубы) | задаёт новые концы; у дуг (`"shape": "arc"`) — только для чтения |
| `tag_head_mm` | марки | переносит голову марки |

Закреплённые (pin) элементы не двигаются — это попадает в ошибки отчёта.
Присоединённые фитинги/соседние сегменты Revit перестраивает сам, как при
ручном перемещении; если он не может — ошибка в отчёте.

## Отчёт после загрузки

Сколько записано, сколько не отмечено, сколько совпало с моделью, сколько
не правили в файле, но изменили в модели (оставлено как в модели); отдельно —
элементы, не найденные в модели; параметры, которых нет у элемента; параметры
только для чтения; значения, которые не записать (пустое у числового,
вложенный объект вместо текста) и ошибки записи Revit.

## Ограничения

- Работает только с текущим документом, не со связями.
- Параметры-ссылки на элементы (`ElementId`, например «Проводник» цепи)
  выгружаются только для чтения — по имени их однозначно не записать.
