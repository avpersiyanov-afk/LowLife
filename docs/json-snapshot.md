# Снимок модели в JSON — «Модель → JSON» / «JSON → модель»

Две кнопки на панели `ToolsSchedules` («Спецификации»), тема `General`
(«Общее») переключателя `_Themes.panel`. Логика — `lib/lowlife/json_snapshot.py`,
настройки — `lib/lowlife/json_snapshot_settings.py`.

Идея: выгрузить нужную часть модели в JSON, отдать файл на анализ (например,
Claude — в том числе в облачной сессии, у которой нет доступа к Revit),
получить исправленный файл и загрузить правки обратно. Модель меняется
**только** кнопкой загрузки — после предпросмотра и одной транзакцией.

## Сценарий

1. **Shift+клик** по «Модель → JSON» — настроить, что выгружать (см. ниже).
   Без настройки выгружаются все элементы активного вида со всеми
   параметрами.
2. **Клик** по «Модель → JSON» → выбрать, куда сохранить `.json`.
3. Отдать файл Claude с задачей, например: «найди устройства СПА без адреса»,
   «пронумеруй адреса по этажам», «заполни пустые параметры LOI по ТЗ».
   Правила формата записаны в сам файл (поле `"readme"`), отдельно объяснять
   их не нужно.
4. **Клик** по «JSON → модель» → выбрать исправленный файл → в списке
   «было → станет» оставить отмеченным то, что записать → «Записать
   отмеченные». Всё пишется одной транзакцией: Ctrl+Z отменяет загрузку
   целиком.

## Настройки выгрузки (Shift+клик)

| Настройка | Что делает |
|---|---|
| **Какие элементы** | Активный вид (план/3D/спецификация) · выделенные элементы · весь документ |
| **Категории** | Имена категорий по одной на строке, кнопка «Выбрать из модели…». Пусто — все категории модели (без аннотаций, осей, уровней, видов) |
| **Параметры** | Имена параметров по одному на строке, кнопка «Выбрать из модели…» (✎ — параметр записываемый). Пусто — все параметры экземпляра |
| Параметры только для чтения | Длины, вычисляемые значения, ссылки — в `"readonly"`, для анализа. По умолчанию вкл. |
| Параметры типа | В `"type_params"`, для анализа. По умолчанию выкл. |
| Пустые значения | Выгружать и незаполненные параметры — включите, если в снимке нужно **заполнять** пустые параметры. По умолчанию выкл. |
| Электрические цепи | Добавляет цепи, куда входят выгружаемые элементы, с панелью и составом цепи. По умолчанию вкл. |
| Координаты и поворот | Точка вставки и поворот / начало-конец линейного элемента, мм — **можно править** (см. «Перемещение»). По умолчанию выкл. |
| Марки | Марки выгружаемых элементов (на активном виде или на всех видах) — положение головы **можно править**. По умолчанию выкл. |
| Помещения и пространства | Раздел `"rooms"` (текущая модель **и связи**) и у каждого элемента — `"room"`/`"space"`, где он стоит. Только для анализа. По умолчанию выкл. |
| Каталог типоразмеров | Раздел `"catalog"`: загруженные семейства/типоразмеры выбранных категорий (или категорий выгружаемых элементов) — из него выбирать, что создавать в `"new"`. По умолчанию выкл. |
| **Параметры помещений** | Какие параметры помещений/пространств добавить в `"rooms"` (кнопка «Выбрать из модели…»). Для воздушного баланса — расходы пространств |

Настройки можно выгрузить/загрузить файлом (кнопки внизу окна), как и у
остальных кнопок.

## Формат файла (version 1)

```json
{
  "format": "lowlife-snapshot",
  "version": 1,
  "readme": ["…правила…"],
  "document": {"title": "…", "path": "…"},
  "exported_at": "2026-09-29 12:00:00",
  "settings": {"scope": "view", "view": "…", "categories": [], "param_filter": null, "…": "…"},
  "elements": [
    {
      "id": 123456,
      "uid": "5a1c…-0001e240",
      "category": "Пожарная сигнализация",
      "family": "…",
      "type": "…",
      "level": "Этаж 01",
      "params":      {"Комментарии": "…"},
      "readonly":    {"…": "…"},
      "type_params": {"…": "…"},
      "circuit":     {"panel": "<uid>", "elements": ["<uid>", "…"]},
      "location":    {"point_mm": [1000.0, 2000.0, 0.0], "rotation_deg": 90.0},
      "room":        {"uid": "…", "number": "101", "name": "Офис", "source": "АР.rvt : 1 : …"},
      "space":       {"uid": "…", "number": "101", "name": "…", "source": "текущая модель"},
      "h": {"Комментарии": "3f2a9c01", "@location": "a41c07e2"}
    }
  ],
  "rooms": [
    {
      "uid": "…", "kind": "room", "source": "АР.rvt : 1 : …",
      "number": "101", "name": "Офис", "level": "Этаж 01", "level_elevation_mm": 0,
      "area_m2": 18.4, "volume_m3": 55.2, "height_mm": 3000,
      "boundary_mm": [[[0, 0], [4000, 0], [4000, 4600], [0, 4600]]],
      "params": {"Тип помещения": "Офисное"}
    }
  ],
  "catalog": [
    {"category": "Пожарная сигнализация", "family": "…", "type": "…",
     "placement": "OneLevelBased", "instances": 12, "example_uid": "…"}
  ],
  "new": []
}
```

- **Загружаются обратно `"params"` и `"location"`.** В `"params"` можно
  менять значения и добавлять ключи (имена существующих параметров экземпляра
  этого элемента). Удалённый ключ ничего не меняет.
- Значения — текст как в Revit: числа в единицах проекта, «Да/Нет» —
  `"Да"`/`"Нет"` (понимаются и `true`/`false`, `1`/`0`). Пустая строка
  очищает текстовый параметр; числовой пустой строкой не очистить.
- `"readonly"`, `"type_params"`, `"circuit"`, `"tag"`, `"level"`, `"room"`,
  `"space"`, раздел `"rooms"` и прочее —
  только для анализа, их правки игнорируются. Параметры типа намеренно не
  загружаются: изменение меняло бы все экземпляры типа.
- `"uid"`/`"id"` — связь с элементом (сначала UniqueId, запасной — Id).
- `"h"` — отпечатки значений `"params"` на момент выгрузки, по параметру
  (положение — под ключом `"@location"`).
  По ним загрузка различает:
  - значение в файле не правили → не пишется, даже если в модели оно с тех
    пор изменилось (иначе загрузка откатила бы чужую работу);
  - правили в файле, а в модели осталось как было → обычная правка;
  - правили в файле **и** изменили в модели после выгрузки → конфликт: ⚠ в
    списке, по умолчанию **не отмечено**. Добавленный в `"params"` параметр
    считается изначально пустым — если в модели он уже заполнен, это тоже
    конфликт.
- Новые элементы создаются только из раздела `"new"` (см. ниже); записи,
  добавленные в `"elements"`, игнорируются. Ничего не удаляется: элемент из
  файла, которого нет в модели, попадает в отчёт.

## Перемещение (`"location"`)

Координаты — в мм, в системе координат проекта (внутреннее начало Revit),
та же, что при выгрузке.

| Ключ | У кого | Что делает изменение |
|---|---|---|
| `point_mm` `[x, y, z]` | точечные элементы (оборудование, устройства, помещения) | перемещает элемент в эту точку |
| `rotation_deg` | точечные элементы с поворотом | поворачивает вокруг вертикали до этого угла (абсолютное значение, градусы) |
| `start_mm`, `end_mm` | прямые линейные элементы (лотки, линии, трубы) | задаёт новые концы; у дуг (`"shape": "arc"`) — только для чтения |
| `tag_head_mm` | марки | переносит голову марки |

Закреплённые (pin) элементы не двигаются — это попадает в ошибки отчёта.
Присоединённые фитинги/соседние сегменты Revit перестраивает сам, как при
ручном перемещении; если он не может — ошибка в отчёте.

## Помещения и пространства (`"rooms"`)

Берутся размещённые помещения (Rooms) и пространства (MEP Spaces) из
текущей модели и из всех загруженных связей — архитектурные помещения
обычно лежат в связи АР. Координаты связи переводятся в систему координат
проекта, поэтому контуры помещений и `"location"` элементов сравнимы
напрямую.

- **Какие помещения попадают:** все, где стоит хоть один выгружаемый
  элемент, плюс все помещения на тех же уровнях (сравнение по отметке, не
  по имени уровня — в АР и в вашей модели имена могут отличаться), чтобы
  были видны и пустые помещения. При выгрузке всего документа — все.
- **Что в записи:** номер, имя, уровень и его отметка, площадь (м²), объём
  (м³, если Revit его считает), высота, контуры `"boundary_mm"` (первый —
  внешний, остальные — вырезы вокруг колонн/шахт; дуги разбиты на отрезки) и
  параметры из списка «Параметры помещений».
- **Привязка элемента:** точка элемента внутри помещения (с пробой на 300 мм
  выше — для устройств ровно на отметке пола), иначе ближайшее помещение не
  дальше 90 мм от контура (оборудование, утопленное в стену) — та же логика,
  что у кнопки «Запись номера помещения».
- Раздел только для анализа. Пространства текущей модели можно выгрузить
  ещё и как обычные элементы (категория «Пространства») — тогда их
  записываемые параметры (например, расчётные расходы) правятся через
  `"params"`.

Примеры задач: площади и количество устройств по помещениям, помещения без
извещателей/розеток, воздушный баланс по пространствам (сумма расходов
воздухораспределителей с одним `"space"` против расхода пространства).

## Создание элементов (`"new"`)

В выгрузке всегда есть пустой раздел `"new"`. Каждая добавленная туда
запись при загрузке превращается в строку «＋ создать …» в списке
предпросмотра (отмечена по умолчанию).

```json
"new": [
  {"family": "Извещатель", "type": "ИП212-64", "point_mm": [12000, 4500, 2700],
   "level": "Этаж 01", "rotation_deg": 0, "params": {"Адрес": "2.14"}},
  {"copy_of": "<uid существующего экземпляра>", "point_mm": [15000, 4500, 2700]}
]
```

| Поле | Обязательно | Что это |
|---|---|---|
| `family` + `type` | да (или `copy_of`) | Загруженный типоразмер — имена как в `"catalog"` |
| `copy_of` | вместо family/type | Скопировать существующий экземпляр в новую точку. Нужно для семейств на основе грани/рабочей плоскости, которые по точке не ставятся: копия сохраняет основу. Вместе с `type` — копия с заменой типоразмера того же семейства. В каталоге для этого есть `"example_uid"` |
| `host` | нет | uid стены/потолка текущей модели — для семейств на основе стены |
| `point_mm` | да | Точка вставки, мм, в тех же координатах, что `"location"` |
| `level` | нет | Имя уровня текущей модели; без него — ближайший уровень снизу |
| `rotation_deg` | нет | Поворот вокруг вертикали, градусы |
| `params` | нет | Значения параметров экземпляра, как в `"params"` |

- Вставка — как у кнопки «Расстановка РМ, АМ, МДУ» (СПА): первое, что примет Revit (с
  основой и уровнем → с основой → по уровню → без привязки; без уровня — уровень
  сразу назначается параметром, если Revit позволяет), затем элемент
  сдвигается точно в `point_mm` и поворачивается — высота не зависит от того,
  как семейство трактует Z точки вставки.
- **Дубли не создаются:** если в 10 мм от точки уже стоит экземпляр того же
  типоразмера (в модели или выше в том же `"new"`), запись пропускается —
  повторная загрузка того же файла ничего не удвоит.
- Ошибки в записи (нет такого типоразмера/уровня, не три числа в точке)
  попадают в отчёт, остальные записи создаются. Если элемент создан, а
  часть параметров не записалась — он засчитан, замечание в отчёте.

Типичный сценарий расстановки: выгрузить с помещениями и каталогом →
попросить Claude расставить оборудование по правилам (шаг, отступы от стен,
«в каждом помещении …») по контурам `"boundary_mm"` → загрузить. Стены,
двери и препятствия Claude не видит (их нет в файле) — результат проверить
на плане; отменить всё целиком — Ctrl+Z.

## Отчёт после загрузки

Сколько записано/создано, сколько не отмечено, сколько совпало с моделью, сколько
не правили в файле, но изменили в модели (оставлено как в модели); отдельно —
элементы, не найденные в модели; параметры, которых нет у элемента; параметры
только для чтения; значения, которые не записать (пустое у числового,
вложенный объект вместо текста, ошибки в записях `"new"`), записи `"new"`,
пропущенные как дубли, и ошибки/замечания Revit при записи.

## Ограничения

- Элементы выгружаются и правятся только в текущем документе; из связей
  берутся только помещения и пространства (для анализа).
- Параметры-ссылки на элементы (`ElementId`, например «Проводник» цепи)
  выгружаются только для чтения — по имени их однозначно не записать.
