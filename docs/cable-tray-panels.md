# Tray*.panel — создание кабельных лотков

Пять панелей на ленте LowLife, каждая — один конструктив лотка, с четырьмя
одинаковыми кнопками («Лоток СПЗо» / «Лоток СПЗп» / «Лоток СБ» / «Лоток СС» —
по системе, для которой прокладывается лоток). Всего 20 кнопок, вся логика —
в `lib/lowlife/cable_tray.py` (`run_create_cable_tray_button`), скрипты
кнопок только передают туда подстроку имени нужного типа.

| Панель (папка) | Заголовок на ленте | Конструктив | Подстрока типа |
|---|---|---|---|
| `TrayLadder.panel` | Лестничный лоток | Лестничный (ЛЛ) | `<Система>_ЛЛ_1.5_СЦ` |
| `TrayUnperforated.panel` | Неперфорированный лоток | Неперфорированный (ЛН) | `<Система>_ЛН_1.5_СЦ` |
| `TrayPerforated.panel` | Перфорированный лоток | Перфорированный (ЛП) | `<Система>_ЛП_1.5_СЦ` |
| `TrayWire.panel` | Проволочный лоток | Проволочный (ЛВ) | `<Система>_ЛВ_1.5_СЦ` |
| `TrayRoof.panel` | Лотки на кровле | Перфорированный, горячеоцинкованный | `<Система>_ЛП_1.5_ГЦ` |

`<Система>` — одно из `СПЗо`/`СПЗп`/`СБ`/`СС`, соответствует одной из четырёх
кнопок на каждой панели.

## Что делает кнопка

1. Ищет среди `CableTrayType` проекта ровно один тип, содержащий заданную
   подстроку (например `СПЗо_ЛЛ_1.5_СЦ`) — тип должен уже существовать в
   проекте (загружен из шаблона/файла типоразмеров), кнопка его не создаёт.
   Если типов с такой подстрокой 0 или больше 1 — алерт с остановкой скрипта,
   без угадывания.
2. Ищет среди пользовательских рабочих наборов проекта ровно один, чьё имя
   содержит «КНК», и переключает его в активный (`WorksetTable.SetActiveWorksetId`)
   — так новый лоток создаётся в правильном рабочем наборе.
3. Запускает штатный интерактивный инструмент Revit «Лоток» уже с найденным
   типом через `UIDocument.PostRequestForElementTypePlacement` — дальше
   пользователь рисует лоток мышью в модели как обычно.

Если версия Revit не поддерживает `PostRequestForElementTypePlacement` —
кнопка всё равно переключает рабочий набор и сообщает, какой тип выбрать
вручную в инструменте «Лоток».

## Почему не через `*_settings.py`

В отличие от СКС/СКУД/СПС, здесь нет окна настроек: тип лотка на кнопку —
константа в её `script.py` (одна кнопка — один жёстко заданный тип), а
ключевое слово рабочего набора («КНК») общее для всех 20 кнопок
(`cable_tray.DEFAULT_WORKSET_FILTER`). Заводить JSON-настройки под пять
статичных таблиц соответствий было бы лишней прослойкой без реальной
изменчивости — если имена типов лотков в проекте изменятся, их правят прямо
в `script.py` каждой кнопки.

## Темы (`_Themes.panel`)

Все пять панелей и все 20 кнопок зарегистрированы в `panel_themes.THEMES`
под своей темой — `u"КНК"` (название — по рабочему набору, в который они
переключают проект, а не по дисциплине: создание лотков не привязано к
одной конкретной системе). В переключателе тем (`ThemeSelector.combobox`)
это пункт «КНК (лотки)». Выбор темы «КНК» показывает только Tray*.panel;
любая другая тема их скрывает — как и остальные дисциплины.

Так как у каждой Tray*.panel есть свой `title:` в bundle.yaml (например,
«Лестничный лоток» у `TrayLadder.panel`), а `RibbonPanel.Name` в рантайме —
это отображаемый заголовок, а не имя папки, все пять панелей добавлены в
`PANEL_RIBBON_NAMES` (иначе `_find_panel` искал бы панель по имени папки
`"TrayLadder"` и не находил бы её на ленте — тот самый повторяющийся баг
«панель игнорирует переключатель тем» из-за несовпадения title≠имя папки).
