# Марки помещений из связи (RoomTags)

Кнопка `Tools.panel/RoomTags` («Марки помещений»). Помещения (Room) живут
в связанной модели АР, а марки нужны в нашем документе на активном плане.
Зарегистрирована в теме `General` переключателя `_Themes.panel` (рядом с
`RoomInfo`). Логика — в `lib/lowlife/room_tags.py`, скрипт кнопки тонкий.

## Что делает за один запуск

Работает по активному виду (`ViewPlan` — план этажа/потолочный;
на других видах кнопка сообщает и выходит). **Shift+клик** (`EXEC_PARAMS.config_mode`)
вместо активного вида открывает список всех планов проекта (без шаблонов)
с множественным выбором — марки обновляются сразу на всех выбранных
планах в одной транзакции.

Пользователь выбирает типоразмер марки из списка — это все загруженные
типоразмеры категории «Марки помещений» (перечисляются через
`Family.GetFamilySymbolIds`, чтобы не потерять ещё не вставленные — см.
грабли в `CLAUDE.md`).

Затем в одной транзакции:

1. **Чинит или удаляет «мёртвые» марки.** Когда АР удаляет и заново
   создаёт помещение (пусть даже с тем же номером), марка в нашем
   документе теряет привязку и показывает `???`. Перепривязать её через
   API нельзя, поэтому под головой каждой такой марки (`TagHeadPosition`)
   ищется помещение связи. Нашлось — старая марка заменяется новой
   (положение головы и наличие полки-выноски сохраняются). Помещения под
   маркой уже нет — **непривязанная марка удаляется**.
   Состояние привязки (`_stale_kind`): `live` (помещение на месте —
   только перетипировать), `dead` (связь удалена из проекта либо
   `TaggedRoomId` не разрешается в Room связи — чинить/удалять),
   `link_unloaded` (связь сейчас выгружена — **не трогаем**, нельзя
   понять, жива ли привязка). Дополнительно к `dead` чинятся марки с
   `RoomTag.IsOrphaned == True`.
2. **Приводит типоразмер** всех живых марок помещений на виде к
   выбранному (единый вид марок на листе).
3. **Добавляет недостающие марки** для помещений связей, которые
   попадают на уровень вида (отметка центра в пределах
   `_LEVEL_TOL_MM` = 1500 мм от отметки уровня вида) и в область подрезки
   (если она включена), но ещё не помечены.

Марки для помещений связи создаются единственным доступным способом —
`doc.Create.NewRoomTag(LinkElementId(link.Id, room.Id), UV, view.Id)`
(аналога `IndependentTag.Create` для помещений в API нет).

## Обход грабли с подложкой

При включённой подложке Revit отказывается ставить марку помещения
(«point is not in a room») либо сажает её на помещение с подложки. Перед
работой кнопка снимает подложку активного вида
(`SetUnderlayBaseLevel(InvalidElementId)`), а в блоке `finally`
возвращает прежние базовый/верхний уровни подложки.

## Сводка по завершении

Показывает счётчики: добавлено, пересоздано `???`, удалено `???` без
помещения, сменён типоразмер, уже стояли, помещений вне области вида,
помещений без точки размещения; при ненулевых значениях — «пропущено
(связь выгружена)» и «`???` не удалось убрать» (редкий случай, когда сам
`doc.Delete` не прошёл). Ни один из этих случаев не считается ошибкой.
