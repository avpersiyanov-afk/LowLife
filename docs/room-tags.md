# Марки помещений из связи (RoomTags)

Кнопка `ToolsRooms.panel/RoomTags` («Марки помещений»). Помещения (Room)
живут в связанной модели АР, а марки нужны в нашем документе на активном
плане. Логика — в `lib/lowlife/room_tags.py`, скрипт кнопки тонкий.

## Что делает за один запуск

Работает по активному виду (`ViewPlan` — план этажа/потолочный;
на других видах кнопка сообщает и выходит). **Shift+клик** (`EXEC_PARAMS.config_mode`)
вместо активного вида открывает список всех планов проекта (без шаблонов)
с множественным выбором — марки обновляются сразу на всех выбранных
планах в одной транзакции.

Пользователь выбирает типоразмер марки из списка — это все загруженные
типоразмеры категории «Марки помещений» (перечисляются через
`Family.GetFamilySymbolIds`, чтобы не потерять ещё не вставленные — см.
грабли в `CLAUDE.md`).

Затем в одной транзакции:

1. **Чинит или удаляет «битые» марки.** Марка считается битой, если
   выполняется любое из:
   - `_resolve_tag_room` вернул `dead` — `TaggedRoomId` не разрешается в
     Room (связь удалена из проекта либо помещение в связи исчезло);
   - `RoomTag.IsOrphaned == True`;
   - `_room_ok(room)` == False — это не Room (id занял другой элемент
     после пересоздания помещений), либо Room не размещён (нет
     `Location`) / не окружён (`Area == 0`);
   - **марка без выноски** (`HasLeader == False`), а под её головой
     (`_room_under_tag_key` → `_find_link_room_at(TagHeadPosition)`) в
     связи лежит **другое** помещение, чем то, на которое она ссылается
     (`_tagged_room_key`). После того как АР удалил и заново создал
     помещения, `ElementId`'ы сдвигаются: старая ссылка формально ещё
     разрешается в какой-то Room, но не в тот, и Revit рисует `?`.

   Список марок вида собирается двумя коллекторами — вид-скоуп
   `FilteredElementCollector(doc, view.Id)` **плюс** общий сбор с
   фильтром `OwnerViewId == view.Id` (осиротевшие марки из вид-скоупа
   иногда выпадают), с дедупликацией по `Id`.

   Под головой битой марки (`TagHeadPosition`) ищется помещение связи.
   Нашлось — старая марка заменяется новой (положение головы и наличие
   полки-выноски сохраняются). Не нашлось — **марка удаляется** (толку
   от неё нет).

   `link_unloaded` (связь, на которую смотрит марка, сейчас выгружена) —
   **не трогаем**: нельзя понять, жива ли привязка. Считается отдельно
   (`stats["link_unloaded"]`).
2. **Приводит типоразмер** всех нормальных марок помещений на виде к
   выбранному (единый вид марок на листе).
3. **Добавляет недостающие марки** для помещений связей, которые
   попадают на уровень вида (отметка центра в пределах
   `_LEVEL_TOL_MM` = 1500 мм от отметки уровня вида) и в область подрезки
   (если она включена), но ещё не помечены.

Марки для помещений связи создаются единственным доступным способом —
`doc.Create.NewRoomTag(LinkElementId(link.Id, room.Id), UV, view.Id)`
(аналога `IndependentTag.Create` для помещений в API нет).

## Обход грабли с подложкой

При включённой подложке Revit отказывается ставить марку помещения
(«point is not in a room») либо сажает её на помещение с подложки. Перед
работой кнопка снимает подложку активного вида
(`SetUnderlayBaseLevel(InvalidElementId)`), а в блоке `finally`
возвращает прежние базовый/верхний уровни подложки.

## Итог

Кнопка отрабатывает молча — окна-отчёта нет. `room_tags.run` всё же
возвращает словарь-статистику (`added`, `recreated`, `deleted`, `retyped`,
`already`, `link_unloaded`, `orphan_unresolved`, `out_of_view`,
`room_no_point`) на случай, если сводка снова понадобится.
