# SKUD.panel — требования к семействам и параметрам

Четыре кнопки на панели `SKUD` для автоматизации проекта СКУД (контроль
доступа): от расставленного на плане оборудования и заведённых цепей — до
готовых КЖ, спецификации кабеля и структурной схемы. Настройки — отдельные
от `SCS.panel` (свой JSON-файл `%APPDATA%\pyRevit\LowLifeSKUD_settings.json`,
своё окно). Ничего из имён параметров/семейств не хранится в репозитории —
всё вводится в окне настроек при первом запуске.

Естественный порядок запуска — в этом порядке (каждая следующая кнопка
использует результат предыдущей), как в `SCS.panel`:

0. **Параметры СКУД** (`SetupParameters`) — окно настроек + проверка/
   привязка параметров из ФОП. Запускать первым.
1. **Цепи и кабели** (`AssignCircuitsAndCables`) — находит контроллеры и их
   цепи, назначает адреса подключённым устройствам, выбирает тип кабеля по
   словарю, пишет имя нагрузки, маркирует контроллеры.
2. **Длины и маркировка** (`CalcSkudLengths`) — считает длину проводника (по
   катетам рядом с контроллером, иначе по графу трассы), пишет длину в
   трубе/лотке раздельно, способ прокладки, марку устройств и список цепей
   на узлах маршрута.
3. **Структурная схема** (`BuildSkudSchematic`) — размножает типовую группу
   структурной схемы по контроллерам, копирует адреса, соединяет линиями.

Маркировка намеренно живёт внутри кнопки длин, а не отдельной кнопкой:
марка устройства — это перенос уже известного адреса, а список цепей на
узлах собирается из пути цепи, который на этом шаге уже посчитан как
список (отдельной кнопке пришлось бы разбирать его обратно из текста
`"F1.1 -> F1.2"` в параметре «Маршрут цепи»).

## 0. Параметры СКУД (SetupParameters)

Аналогично `SetupParameters` в `SCS.panel` — проверяет привязку параметров
СКУД к нужным категориям, добавляет недостающие привязки из подключённого
файла ФОП. Ничего не выдумывает: если определения параметра нет ни в
проекте, ни в ФОП — только сообщает об этом.

## 1. Цепи и кабели (AssignCircuitsAndCables)

### Контроллеры

- Ищутся среди `OST_ElectricalEquipment`: рабочий набор содержит ключевое
  слово («Ключевое слово рабочего набора контроллеров»), **и** имя типа
  (`Symbol.Name`) содержит ключевое слово («Ключевое слово в имени типа
  контроллера»).
- У контроллера уже должен быть заполнен параметр «Адрес устройства»
  (вводится пользователем вручную при расстановке оборудования) — без него
  контроллер пропускается.

### Цепи и устройства

- У цепи — параметр «Панель» (контроллер) со значением, равным `Name`
  контроллера.
- Первое неисключённое устройство цепи (кроме самого контроллера) — то, на
  которое распространяется расчёт. Устройства, чьё имя семейства содержит
  слово из «Ключевые слова резервных портов», не берутся.

### Что записывается

- На устройство: «Адрес устройства» по маске `{адрес контроллера}.{N}`, где
  `N` — простой порядковый номер подключённого устройства в пределах одного
  контроллера (по всем цепям контроллера, без деления по типу устройства).
- На цепь: «Имя нагрузки» (`Обозначение.Адрес`, из параметра типа устройства
  «Обозначение» и записанного выше адреса), тип кабеля (параметр «Проводник»)
  — по словарю «тип устройства : тип кабеля», вводимому построчно в окне
  настроек (формат `ключевое_слово:тип_кабеля`, по одному на строку).
- На контроллер: параметр «Маркировка контроллера» = его же адрес.

## 2. Длины и маркировка (CalcSkudLengths)

### Порог "рядом с контроллером"

Прямое 3D-расстояние между контроллером и устройством сравнивается с
порогом («Порог «рядом с контроллером», м», в метрах).

- **Меньше порога** — длина считается по катетам:
  `|dx| + |dy| + |dz|`, умноженным на коэффициент запаса («Коэффициент
  запаса для расчёта по катетам»). Весь объём пишется в «Длина проводника в
  трубе» — способ прокладки всегда труба, «Длина проводника в лотке» = 0.
- **Больше порога** — длина считается по графу уже адресованных узлов
  трассы СКУД (тот же алгоритм, что в `SCS.panel`: A* по адресам,
  `calc_lengths` с разбивкой по способу прокладки узла). Линии детализации,
  по которым физически идёт трасса, **уже существуют в проекте** — их
  рисует пользователь вручную, кнопка их только читает (узлы маршрута СКУД
  расставляются и адресуются так же, как в СКС — свой тип для узлов/
  стояков, свои параметры «Адрес узла»/«Предыдущий адрес»/«Ближайший узел
  маршрута», настраиваемые отдельно от СКС).

### Что записывается

- «Длина проводника» (сумма трубы и лотка — то же самое число, что попадает
  и в КЖ, и в спецификацию, без отдельного пересчёта или переноса длины из
  цепи), «Длина проводника в трубе», «Длина проводника в лотке» —
  раздельно (в отличие от СКС, где труба и труба-открыто объединяются в
  один параметр).
- «Способ прокладки» — текст по шаблонам с `{}` для метров, на основе
  значений «в трубе»/«в лотке».
- «Маршрут цепи» — адреса узлов через `->` (пусто для случая "рядом с
  контроллером", т.к. там нет узлов графа).
- «Марка устройства» = значение «Адрес устройства» (перенос, без пересчёта).
- «Список цепей» на каждом узле маршрута, через который проходит хотя бы
  одна цепь (накапливается прямо во время расчёта путей — путь на этом
  шаге уже есть списком адресов).

## 3. Структурная схема (BuildSkudSchematic)

### Типовая группа-эталон

Пользователь заранее вручную собирает в проекте Revit-**группу**: внутри —
схемные семейства устройств одного (эталонного) контроллера в некотором
эталонном взаимном расположении, плюс рамка из линий аннотации (чисто
визуальная, не участвует в расчётах). Имя этой группы указывается в
настройках («Имя типовой группы-эталона»).

### Точка вставки

При запуске кнопка просит **один клик** на чертёжном виде — это точка,
от которой начинается автоматическая раскладка копий типовой группы (по
числу найденных контроллеров с адресом и подключёнными устройствами),
рядами по настраиваемому числу узлов в ряду и с настраиваемым отступом.

### Сопоставление устройств

Схемные семейства внутри каждой вставленной копии группы сопоставляются с
реальными устройствами этого контроллера **по категории** (считыватель ↔
считыватель, замок ↔ замок и т.д. — правила категорий задаются построчно в
настройках, формат `имя_категории:ключевые_слова`). В пределах одной
категории, если устройств несколько — по порядку адреса. Если реальных
устройств какой-то категории у контроллера больше, чем схемных мест в
типовой группе — лишние остаются без пары, об этом пишется в отчёте (новые
схемные семейства сверх группы не создаются).

### Что записывается

- Параметр адреса на схемном семействе — то же значение, что и «Адрес
  устройства» у сопоставленного реального устройства (либо адрес
  контроллера — для семейства с категорией «контроллер»).
- Линии детализации (`DetailLine`) — прямые отрезки от схемного семейства
  контроллера до каждого сопоставленного схемного устройства (топология
  "звезда", без учёта реальной трассы), рисуются на активном виде поверх
  вставленной копии группы.

## Какие общие параметры (ФОП) нужно завести под свой проект

Аналогично `docs/scs-panel.md` — все текстовые (кроме отдельно помеченных),
экземпляра (кроме отдельно помеченного). Реальные имена придумываются
пользователем и вписываются в окно настроек.

- **Обобщённые модели** (узлы маршрута/стояков СКУД): «Адрес узла»,
  «Предыдущий адрес», «Тип прокладки кабеля», «Список цепей»
  (многострочный) — те же по смыслу параметры, что в СКС, но отдельный
  набор значений/id типов, настраиваемый независимо.
- **Устройства и контроллеры** (Коммуникационные устройства /
  Электротехнические изделия / Датчики данных / Электрооборудование):
  «Ближайший узел маршрута» — экземпляра, у обоих; «Адрес устройства» —
  экземпляра; «Обозначение» — типа устройства; «Маркировка контроллера» —
  экземпляра контроллера; «Марка устройства» — экземпляра устройства.
- **Электрические цепи** (`OST_ElectricalCircuit`): «Панель» (контроллер),
  «Проводник» (тип кабеля), «Маршрут цепи», «Способ прокладки» —
  текстовые; «Длина проводника», «Длина проводника в трубе», «Длина
  проводника в лотке» — числовые; «Имя нагрузки» — обычно нативный
  параметр Revit MEP.
- Не параметр, а соглашение: рабочий набор контроллеров и имя их типа
  должны содержать соответствующие ключевые слова; словарь «тип устройства
  → тип кабеля» и категории устройств для структурной схемы задаются
  ключевыми словами в окне настроек, не хранятся в репозитории.
