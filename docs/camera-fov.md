# СОТ · Зоны обзора видеокамер

Кнопка `SOT.panel/CameraFov` — **«Зоны обзора»**. Строит на активном виде
зону обзора выбранных видеокамер как область заливки (`FilledRegion`) и
обрезает её по границе помещения из связанной модели. Это отдельный
инструмент, не связанный со структурной схемой СОТ: логика и настройки —
в `lib/lowlife/sot_fov.py`, свой файл настроек
`%APPDATA%\pyRevit\LowLifeCameraFov_settings.json`.

Портирование Dynamo-скрипта «зона обзора камеры» на чистый Revit + разбор
исходника см. в истории обсуждения; здесь — итоговое поведение.

## Порядок работы

1. **Сначала нажать кнопку**, затем выбрать камеры в модели. Фильтр
   выбора (`ISelectionFilter`) пропускает только категорию **«Охранная
   сигнализация»** (`OST_SecurityDevices`) — обычно к ней относятся
   семейства камер. Предварительное выделение не используется.
2. Активным должен быть **план этажа/потолка или чертёжный вид**
   (`ViewPlan` / `ViewDrafting`). На 3D, разрезе, фасаде и листе кнопка
   останавливается с сообщением.
3. Построение идёт в одной транзакции; в конце в окне вывода pyRevit —
   отчёт по каждой камере (см. ниже).

**Shift+клик** (`EXEC_PARAMS.config_mode`) открывает окно настроек.

## Как считается зона

Для каждой камеры:

- **Направление «взгляда»** определяется по очереди:
  `FamilyInstance.FacingOrientation` → `Transform.BasisY` → `BasisX` →
  `HandOrientation⟂` (первый источник с ненулевой горизонтальной
  проекцией). `FacingOrientation` учитывает поворот и зеркалирование
  **самого экземпляра** в модели.
  - Если камеру разворачивают **не поворотом экземпляра, а параметром
    внутри семейства** (тогда `FacingOrientation` не меняется, и все зоны
    смотрят в одну сторону) — укажите имя этого параметра в
    **`rotation_param_name`**. Его значение прибавляется к направлению
    (против часовой стрелки). Это и есть «Вращение (поворот)» из исходного
    Dynamo-скрипта.
  - **`direction_offset_deg`** — фиксированная поправка, одинаковая для
    всех камер (когда геометрия семейства смотрит не «вперёд»).
  - В отчёте по каждой камере печатается использованный источник и
    итоговый азимут — видно, совпал ли он с реальным направлением.
- **Горизонтальный сектор** — угол из параметра «угол обзора», радиус —
  из параметра «дальность».
- **Учёт высоты установки.** Если заданы параметры высоты монтажа, наклона
  оптической оси вниз и вертикального угла обзора — зона считается как
  проекция конуса на плоскость расчёта:

  ```
  near = h / tg(наклон + вертикальный/2)     (ближняя мёртвая зона)
  far  = h / tg(наклон − вертикальный/2)     (дальняя граница)
  ```

  При `наклон ≤ вертикальный/2` верхний луч уходит в горизонт → дальняя
  граница берётся из параметра дальности. Высота `h` — либо из параметра,
  либо «отметка точки вставки минус отметка уровня камеры», за вычетом
  **высоты плоскости расчёта** (0 — пол, 1500 — плоскость лиц и т.д.).
  Если этих параметров нет — зона строится как плоский сектор от точки
  камеры (поведение исходного скрипта).

- **Обрезка по помещению.** `room_rings_for_point` перебирает все
  **загруженные** связи, у каждого `Room` берёт контур
  (`GetBoundarySegments`, отделка/оси), тесселлирует и переводит в
  координаты хоста (`Curve.CreateTransformed`). Помещение камеры
  определяется **2D-тестом «точка внутри контура по XY»** — а не
  `Room.IsPointInRoom`, который отсекал камеру под потолком (он
  чувствителен к Z, а камера почти всегда выше объёма помещения). Если по
  XY подошло несколько помещений (этажи друг над другом) — берётся то,
  чей вертикальный габарит содержит отметку камеры, иначе ближайшее по
  высоте. Точка вне всех контуров → ближайшее помещение в пределах 90 мм
  («камера сидит в стене»).

  Если у помещения `GetBoundarySegments` не отдал вообще ни одного
  пригодного контура (разомкнутая/повреждённая граница — нередко у
  помещений сложной формы) — резерв: сечение уже готового **тела**
  помещения, которое сам Revit строит для площади/объёма
  (`_room_solid_rings` → нижняя горизонтальная грань тела через
  `_horizontal_face_rings`). Работает для помещений любой формы —
  вогнутых, с несколькими контурами (внутренний двор), с дугами.

- **Препятствия внутри помещения (колонны и т.п.).** Отдельно от границы
  помещения и **независимо от неё**: `_prepare_obstacle_sources` собирает
  элементы категорий `obstacle_categories` (по умолчанию
  `OST_Columns, OST_StructuralColumns`) из **текущей модели и ВСЕХ
  связей** — колонны обычно стоят в отдельной конструктивной связи, не в
  той, где помещения, и сама `Room` чаще всего не огибает их контуром
  (если колонна не отмечена «граница помещения»). Для каждого элемента,
  чей вертикальный габарит захватывает высоту плоскости расчёта, берётся
  его реальный горизонтальный контур (`_footprint_rings` — то же сечение
  тела, что и у помещения, а не прямоугольник bounding box) и
  подмешивается к контуру помещения как ещё одна «дыра». Геометрия
  каждого препятствия считается один раз за весь запуск кнопки
  (`ring_cache`), не на каждую камеру.

  Затем **каждый луч** сектора укорачивается до первого пересечения с
  контуром — помещения или препятствия, смотря что ближе
  (`_clip_distance`) — поэтому за колонной в зоне остаётся характерная
  «тень». Работает и с вогнутыми помещениями, и с несколькими
  препятствиями сразу; в их вершины добавляются точные лучи для чётких
  границ тени. В отчёте по камере пишется, как нашлось помещение и
  сколько препятствий попало на пути.

Контур зоны — звёздный многоугольник от точки камеры, либо кольцевой
сектор при ненулевой мёртвой зоне (`_zone_curveloop`). Рисуется одна
`FilledRegion` выбранного типа; граница — на автоздаваемой подкатегории
линий (по умолчанию «СОТ_Зона обзора»).

## Идемпотентность

В параметр «Комментарии» области заливки пишется `<метка>|<Id камеры>`
(метка по умолчанию `CCTV_FOV`). При повторном запуске `_delete_previous`
удаляет с активного вида зоны **выбранных** камер (по этой метке) и
дуги DORI (по имени стиля линии `«… · DORI»`), затем строит заново.
Зоны других камер на виде не трогаются.

## Зоны DORI (необязательно)

При включённом флаге и заданном горизонтальном разрешении матрицы
добавляются концентрические дуги на расстояниях идентификации /
распознавания / наблюдения / обнаружения (250 / 125 / 63 / 25 пикс/м,
EN 62676-4):

```
d = H_res / (2 · пикс/м · tg(горизонтальный угол / 2))
```

Дуги, выходящие за дальность, не рисуются.

## Параметры на семействе камеры

Кнопка **не создаёт** параметров — она читает уже существующие параметры
экземпляра камеры, имена которых заданы в настройках. Значения по
умолчанию имён — от исходного Dynamo-скрипта (`УГО_ПВ_...`), под свой ФОП
их надо поменять.

| Настройка (имя параметра) | Что читается на камере | Тип параметра Revit | Единицы / диапазон | Обязателен |
|---|---|---|---|---|
| `angle_param_name` — «Параметр горизонтального угла обзора» | горизонтальный угол раскрытия сектора | «Угол» → радианы; «Число» → см. `angle_unit` | 1…360°; типично 30–110° | нет, если задана оптика |
| `focal_length_param_name` — «Параметр фокусного расстояния» | фокусное расстояние объектива, для расчёта угла из оптики | «Длина» (→ мм) или «Число» (уже мм) | 1…50 мм; варифокал 2.8–12 мм — берётся текущее значение | нет |
| `distance_param_name` — «Параметр дальности» | максимальный радиус зоны (дальняя граница, если не ограничена расчётом по конусу) | **«Длина»** | 1…100 м; типично 8–40 м | **да** |
| `height_param_name` — «Параметр высоты установки» | высота монтажа камеры над её уровнем | «Длина» | 2…12 м; типично 2.5–4 м. Пусто → «отметка точки вставки − отметка уровня» | нет |
| `rotation_param_name` — «Параметр поворот камеры» | угол разворота камеры ВНУТРИ семейства (когда сам экземпляр не поворачивается) | «Угол» / «Число» | 0…360°. Прибавляется к направлению против часовой стрелки | нет |
| `tilt_param_name` — «Параметр наклона оптической оси вниз» | угол наклона оси камеры вниз от горизонта | «Угол» / «Число» | 0…90°; 0 = смотрит горизонтально; типично 10–35° | нет |
| `vfov_param_name` — «Параметр вертикального угла обзора» | вертикальное поле зрения | «Угол» / «Число» | 10…90°. Пусто, но задана оптика с форматом «ШхВ» → считается из высоты матрицы | нет |

Если параметр **не типа «Длина»/«Угол»**, а «Число» — значение берётся
как есть: длины считаются в миллиметрах, углы — по полю «Единицы углов».

### Как получается горизонтальный угол

1. Если задан `focal_length_param_name`, он найден на камере, и заполнен
   `sensor_format` — угол считается из оптики:
   `θ_h = 2·arctg(ширина_матрицы / (2·f))`; параметр `angle_param_name`
   при этом **не используется**. Если `sensor_format` задан как «ШхВ» —
   так же считается вертикальный угол `θ_v` (если нет `vfov_param_name`).
2. Иначе — из параметра `angle_param_name`.
3. Если не задано ни то, ни другое — кнопка останавливается с сообщением.

## «Не выбирается ни одна камера» — что проверить

1. **Категория семейства камеры.** Выделите камеру в модели → на панели
   «Свойства» вверху написана категория. Если это не «Оборудование систем
   безопасности», а, например, «Устройства связи», «Информационные
   устройства», «Электрооборудование» или «Обобщённые модели» — впишите
   соответствующее имя (`OST_CommunicationDevices` / `OST_DataDevices` /
   `OST_ElectricalEquipment` / `OST_GenericModel`) в поле
   `camera_categories` (Shift+клик), можно несколько через запятую.
2. **Тип активного вида** — план этажа/потолка или чертёжный вид. На 3D,
   разрезе, фасаде, листе, легенде, спецификации кнопка не работает.
3. **Обязательные настройки** — заполнены `distance_param_name`,
   `zone_tag` и один из способов получить угол.

## Отчёт по каждой камере

После запуска в окне вывода pyRevit печатается строка на **каждую**
выбранную камеру: маркер (`OK` / `~` — построена без обрезки / `FAIL`),
кликабельная ссылка на элемент, имя типа и марка, статус и подробность.

Для построенных зон подробность — сводка расчёта:
`азимут 137°, угол 72°, R 0.0–18.3 м; напр.: FacingOrientation + поворот 25.0°; обрезка по помещению: помещение (1 по XY) (312 сегм.); препятствий на пути: 1`.
По ней видно, тем ли направлением пошла зона, как нашлось помещение и
задела ли зона колонну на пути.

| Статус | Причина / что делать |
|---|---|
| `построена` | зона создана и обрезана по помещению |
| `построена (без обрезки — помещение не найдено)` | под точкой камеры нет `Room` ни в одной связи |
| `построена (без обрезки — обрезка дала пустой контур)` | камера впритык к стене или подхватилось чужое помещение — построено без обрезки |
| `нет параметра угла обзора` | у камеры нет параметра `angle_param_name` (и оптика не задана) |
| `нет параметра дальности` | у камеры нет параметра `distance_param_name` |
| `вырожденная геометрия` | подробность уточняет: `угол обзора = 0…` (параметр не заполнен / не тот / не те единицы), `дальность = 0…` (пуст / не «Длина»), `не удалось определить направление [Facing=… / BasisY=… / …]` (векторы для диагностики) |
| `нет точки вставки` | у камеры `Location` не `LocationPoint` |
| `ошибка создания` | `FilledRegion.Create` отклонил контур — увеличьте `ray_count` или упростите помещение |

### Если все зоны смотрят в одну сторону

Камеру разворачивают параметром внутри семейства, а не поворотом
экземпляра. Впишите имя этого параметра в `rotation_param_name`
(Shift+клик). Проверить: в отчёте азимут у разных камер должен стать
разным.

### Если помещения не находятся (все зоны «без обрезки»)

В строке отчёта после «без обрезки —» написана причина:

| Текст в отчёте | Что это значит |
|---|---|
| `в проекте нет связей (RevitLinkInstance)` | архитектурная модель не подгружена как связь Revit |
| `связи есть, но не загружены` | связь в статусе «Выгружено» — Управление связями → Загрузить |
| `в связях (N шт.) нет размещённых помещений` | в связанной модели помещения не расставлены, либо это не та связь (МЭП/КЖ вместо АР) |
| `проверено помещений: N, точка вне всех контуров по XY` | камера по плану вне помещений: вынесена в стену/шахту дальше 90 мм, стоит в коридоре без помещения, или связь смещена/повёрнута относительно площадки (иная система координат) |
| `помещение (из N по XY — ближайшее по высоте)` | помещение найдено, но отметка камеры не попала в габарит ни одного этажа — проверьте отметку установки и «Базовое смещение»/«Смещение сверху» помещений |

Помещения берутся из **всех** загруженных связей — отдельно указывать
файл не нужно. Категория — стандартные «Помещения» (`OST_Rooms`) связи.

### Если у конкретного помещения контур так и не строится

Значит не сработал ни `GetBoundarySegments`, ни резервное сечение тела
(`_room_solid_rings`) — у помещения нет вычисленной геометрии вовсе.
Обычно значит, что оно по-настоящему **не ограничено** (Revit показывает
жёлтый штрих вместо заливки на плане: разрыв в стенах, не расставлены
разделители помещений). Исправляется в архитектурной модели, не в
настройках кнопки.

### Колонны не создают тень / не в счёт «препятствий»

- Проверьте `obstacle_categories` (Shift+клик) — категория колонны должна
  совпадать точно (архитектурная `OST_Columns` и конструктивная
  `OST_StructuralColumns` — это разные категории).
- Колонна физически должна пересекать высоту плоскости расчёта
  (`target_level_offset_mm` над уровнем) — колонна, целиком выше или ниже
  этой отметки (например, подвешенная консоль), в тень не пойдёт.
- В отчёте по камере смотрите хвост строки: `препятствий на пути: N` —
  если 0, а колонна рядом есть, скорее всего она дальше, чем дальность
  камеры + запас, либо не построилась геометрия (нетипичный профиль).

### «Препятствие есть, обрезка дала пустой контур» (зона строится без тени)

Значит совместная обрезка (помещение + все найденные препятствия) выродила
контур в ноль, и кнопка сама откатилась — сначала пробует без препятствий,
затем вовсе без обрезки (статус `ok_clip_failed`, «построена (без обрезки —
обрезка дала пустой контур)»). Обычно это значит, что контур одного из
препятствий **накрывает саму камеру** — тогда лучи «упираются» в свою же
границу почти сразу же во все стороны. Два типовых случая уже
отфильтровываются автоматически (см. `_gather_obstacle_rings`), с пояснением
в отчёте после «не в счёт:»:

- **«N вплотную к камере»** — камера физически смонтирована на этой же
  колонне (или консоль вплотную к ней, ближе ~300 мм) — колонна не может
  «загораживать сама себя», такое препятствие пропускается.
- **«N с подозрительно большим контуром»** — Revit **сшивает (joins)**
  геометрию соприкасающихся элементов; если колонна примыкает к плите
  перекрытия или стене, `get_Geometry` иногда отдаёт их **объединённое**
  тело, и «нижняя грань» такого тела — это контур всего перекрытия, а не
  колонны. Порог — 200 кв. футов (~18.6 м²), больше сечения любой реальной
  колонны. Такие контуры отбрасываются до того, как дойти до обрезки.

Если сообщение всё равно появляется — значит выродился какой-то другой,
не подпадающий под эти два случая контур (например, самопересекающийся
профиль нестандартной колонны). Зона в любом случае строится (кнопка не
падает), просто без тени от этого конкретного препятствия в этот раз;
опишите ситуацию (форма колонны, расстояние до камеры) для более точного
фильтра.

## Единицы (кратко)

- **Углы** (обзор / наклон / вертикальный): тип «Угол» → радианы; тип
  «Число» → по полю `angle_unit` (по умолчанию «авто» = градусы для
  «Числа»).
- **Длины** (дальность / высота / фокусное): тип «Длина» → внутренние
  футы Revit пересчитываются автоматически; тип «Число» → трактуется как
  миллиметры.

## Идеи для более точного расчёта (не реализовано)

- `ReferenceIntersector` с `FindReferencesInRevitLinks = True` по всем
  видимым элементам (не только по категориям `obstacle_categories`) —
  честная трассировка лучей вместо готовых горизонтальных сечений;
  нужен 3D-вид. Текущий способ (сечение тела) уже даёт реальный контур
  препятствия и не требует 3D-вида, но не учитывает наклонные/сложные
  профили колонн так же честно, как трассировка.
- Булево пересечение тел (`BooleanOperationsUtils`) конуса и объёма
  помещения — точная обрезка с учётом высоты помещения/потолка.
