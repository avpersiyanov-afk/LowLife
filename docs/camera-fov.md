# СОТ · Зоны обзора видеокамер

Четыре кнопки на `SOT.panel`, не связанные со структурной схемой СОТ —
логика и общие настройки живут в `lib/lowlife/sot_fov.py`, свой файл
`%APPDATA%\pyRevit\LowLifeCameraFov_settings.json`:

- **«Зоны обзора»** (`CameraFov`) — строит на активном виде зону обзора
  выбранных видеокамер как область заливки (`FilledRegion`), обрезая её
  по границе помещения из связанной модели. Только читает параметры,
  ничего не пишет на камеру.
- **«Навести на помещение»** (`AimCameras`) — наоборот, ничего не рисует,
  а подбирает и **записывает** наклон каждой камеры так, чтобы дальний
  край её зоны приходился на границу помещения (раздел «Автонаведение»
  ниже). Порядок применения: сначала эта кнопка, затем «Зоны обзора».
- **«Проверка параметров»** (`CameraParamsCheck`) — диагностика, ничего
  не строит и не пишет. Берите её первой при подключении нового семейства
  камеры: выбираете одну камеру, кнопка читает ВСЕ параметры её экземпляра
  и типа (`sot_fov.diagnose_camera_params`) и для каждой роли из таблицы
  ниже показывает — настроено ли имя в `LowLifeCameraFov_settings.json`,
  нашёлся ли такой параметр на камере, подходит ли его тип данных
  (Длина/Угол/Текст/Число), и какие ещё параметры камеры того же типа
  данных есть как готовые кандидаты. Отдельно проверяет, что категория
  камеры входит в `camera_categories`, и что `tilt_param_name` — параметр
  ИМЕННО экземпляра (см. «Автонаведение» ниже). Плюс два справочных
  раздела: **геометрия и ориентация** конкретного экземпляра в проекте
  (тот же источник направления, что берёт «Зоны обзора» —
  `FacingOrientation`/`BasisY`/`BasisX`/`HandOrientation`, отражение, хост,
  уровень, итоговый азимут) и **разбор семейства** — кнопка открывает файл
  семейства на редактирование без показа окна (`Document.EditFamily`),
  читает все типоразмеры со значениями параметров, формулы, вложенные
  семейства, тела/вырезы, опорные плоскости, разъёмы, и закрывает без
  сохранения. Раздел с разбором семейства не проверен на живом Revit
  (`sot_fov.inspect_family_definition`) — если какое-то из API-предположений
  не сработает в вашей версии Revit, тот пункт просто покажет ошибку или
  пропустится, остальной отчёт не пострадает. См. `bundle.yaml` кнопки за
  подробным описанием статусов отчёта.
- **«Вид как с камеры»** (`CameraPreviewView`) — создаёт (или обновляет)
  3D-перспективный вид Revit в точке выбранной камеры, смотрящий туда же
  и с полем зрения, подогнанным под её расчётный угол обзора — см. раздел
  «Вид как с камеры» ниже.

Портирование Dynamo-скрипта «зона обзора камеры» на чистый Revit + разбор
исходника см. в истории обсуждения; здесь — итоговое поведение.

## Порядок работы

1. **Сначала нажать кнопку**, затем выбрать камеры в модели. Фильтр
   выбора (`ISelectionFilter`) пропускает только категорию **«Охранная
   сигнализация»** (`OST_SecurityDevices`) — обычно к ней относятся
   семейства камер. Предварительное выделение не используется.
2. Активным должен быть **план этажа/потолка или чертёжный вид**
   (`ViewPlan` / `ViewDrafting`). На 3D, разрезе, фасаде и листе кнопка
   останавливается с сообщением.
3. Построение идёт в одной транзакции; в конце в окне вывода pyRevit —
   отчёт по каждой камере (см. ниже).

**Shift+клик** (`EXEC_PARAMS.config_mode`) открывает окно настроек.

## Как считается зона

Для каждой камеры:

- **Направление «взгляда»** определяется по очереди:
  `FamilyInstance.FacingOrientation` → `Transform.BasisY` → `BasisX` →
  `HandOrientation⟂` (первый источник с ненулевой горизонтальной
  проекцией). `FacingOrientation` учитывает поворот и зеркалирование
  **самого экземпляра** в модели.
  - Если камеру разворачивают **не поворотом экземпляра, а параметром
    внутри семейства** (тогда `FacingOrientation` не меняется, и все зоны
    смотрят в одну сторону) — укажите имя этого параметра в
    **`rotation_param_name`**. Его значение прибавляется к направлению
    (против часовой стрелки). Это и есть «Вращение (поворот)» из исходного
    Dynamo-скрипта.
  - **`direction_offset_deg`** — фиксированная поправка, одинаковая для
    всех камер (когда геометрия семейства смотрит не «вперёд»).
  - В отчёте по каждой камере печатается использованный источник и
    итоговый азимут — видно, совпал ли он с реальным направлением.
- **Горизонтальный и вертикальный угол обзора — ВСЕГДА расчётные.** Не
  вписываются вручную градусами — считаются из физических характеристик
  объектива и матрицы:

  ```
  hfov = 2·arctg(ширина_матрицы / (2·f))
  vfov = 2·arctg(высота_матрицы / (2·f))
  ```

  где `f` — фокусное расстояние (`focal_length_param_name`), матрица —
  формат из `sensor_format_param_name` на камере, либо, если его там нет,
  общий `sensor_format` из настроек. Так угол не расходится с реальным
  объективом сам по себе — особенно важно для вариофокального, у которого
  угол обзора меняется вместе с фокусным расстоянием каждый раз, когда
  его перефокусировали на месте. Радиус зоны — отдельный параметр
  «дальность» (`distance_param_name`), это не оптика, а заявленная
  дальность распознавания/наблюдения самой камеры.
- **Учёт высоты установки.** Если заданы параметр высоты монтажа и наклона
  оптической оси вниз — зона считается как проекция конуса (с уже
  посчитанным выше вертикальным углом) на плоскость расчёта:

  ```
  near = h / tg(наклон + вертикальный/2)     (ближняя мёртвая зона)
  far  = h / tg(наклон − вертикальный/2)     (дальняя граница)
  ```

  При `наклон ≤ вертикальный/2` верхний луч уходит в горизонт → дальняя
  граница берётся из параметра дальности. Высота `h` — либо из параметра,
  либо «отметка точки вставки минус отметка уровня камеры», за вычетом
  **высоты плоскости расчёта** (0 — пол, 1500 — плоскость лиц и т.д.).
  Если высоты или наклона нет — зона строится как плоский сектор от точки
  камеры (поведение исходного скрипта). Наклон можно подобрать
  автоматически кнопкой «Навести на помещение» (см. ниже).

- **Обрезка по помещению.** `room_rings_for_point` перебирает все
  **загруженные** связи, у каждого `Room` берёт контур
  (`GetBoundarySegments`, отделка/оси), тесселлирует и переводит в
  координаты хоста (`Curve.CreateTransformed`). Помещение камеры
  определяется **2D-тестом «точка внутри контура по XY»** — а не
  `Room.IsPointInRoom`, который отсекал камеру под потолком (он
  чувствителен к Z, а камера почти всегда выше объёма помещения). Если по
  XY подошло несколько помещений (этажи друг над другом) — берётся то,
  чей вертикальный габарит содержит отметку камеры, иначе ближайшее по
  высоте. Точка вне всех контуров → ближайшее помещение в пределах 90 мм
  («камера сидит в стене»).

  Если у помещения `GetBoundarySegments` не отдал вообще ни одного
  пригодного контура (разомкнутая/повреждённая граница — нередко у
  помещений сложной формы) — резерв: сечение уже готового **тела**
  помещения, которое сам Revit строит для площади/объёма
  (`_room_solid_rings` → нижняя горизонтальная грань тела через
  `_horizontal_face_rings`). Работает для помещений любой формы —
  вогнутых, с несколькими контурами (внутренний двор), с дугами.

  **Колонны отдельно не обрабатываются.** У колонн обычно есть отделка
  (в архитектурной модели), отмеченная «граница помещения» — Revit сам
  вырезает её контур внутри границы `Room` и отдаёт его через
  `GetBoundarySegments` дополнительным внутренним контуром («дырой»,
  `rings[1:]`). Обрезка по этой границе уже даёт тень от колонны без
  какого-либо отдельного кода: `_clip_distance` укорачивает луч по
  первому пересечению с **любым** контуром помещения — внешним или
  внутренним — одинаково.

Контур зоны — звёздный многоугольник от точки камеры, либо кольцевой
сектор при ненулевой мёртвой зоне (`_zone_curveloop`). Рисуется одна
`FilledRegion` выбранного типа; граница — на автоздаваемой подкатегории
линий (по умолчанию «СОТ_Зона обзора»).

## Идемпотентность

В параметр «Комментарии» области заливки пишется `<метка>|<Id камеры>`
(метка по умолчанию `CCTV_FOV`). При повторном запуске `_delete_previous`
удаляет с активного вида зоны **выбранных** камер (по этой метке) и
дуги DORI (по имени стиля линии `«… · DORI»`), затем строит заново.
Зоны других камер на виде не трогаются.

## Зоны DORI (необязательно)

При включённом флаге и заданном горизонтальном разрешении матрицы
добавляются концентрические дуги на расстояниях идентификации /
распознавания / наблюдения / обнаружения (250 / 125 / 63 / 25 пикс/м,
EN 62676-4):

```
d = H_res / (2 · пикс/м · tg(горизонтальный угол / 2))
```

Дуги, выходящие за дальность, не рисуются.

## Параметры на семействе камеры

Кнопка **не создаёт** параметров — она читает уже существующие параметры
камеры, имена которых заданы в настройках. Значения по умолчанию имён —
от исходного Dynamo-скрипта (`УГО_ПВ_...`), под свой ФОП их надо
поменять.

**Каждый из этих параметров может быть и параметром экземпляра, и
параметром типа** — искать не нужно указывать отдельно, кнопка сама
проверяет сначала экземпляр, и если там пусто (или такого параметра там
нет) — тип (`_find_param`). Это специально ради вариофокальных
объективов: у двух камер одного типа (та же модель, тот же угол обзора и
дальность — уместно хранить параметром ТИПА) фокусное расстояние и
высота установки на практике почти всегда разные и подстроены на месте
— их естественно держать параметрами ЭКЗЕМПЛЯРА. Что чем сделать —
решаете сами по своему семейству, кнопка одинаково находит оба варианта.

**Если в проекте несколько семейств камер называют один и тот же по
смыслу параметр по-разному** (например, у цилиндрической — «Вращение
(поворот)», у купольной — «УГО_Поворот»), в поле настройки можно
перечислить все варианты через `;`: `Вращение (поворот);УГО_Поворот`.
Кнопка проверяет имена по порядку и берёт первое, что нашлось на
конкретной камере (экземпляр, потом тип) — так одна настройка на проект
работает сразу для всех семейств. Кнопка «Проверка параметров» покажет,
какое из перечисленных имён сработало для выбранной камеры.

| Настройка (имя параметра) | Что читается на камере | Тип параметра Revit | Единицы / диапазон | Обязателен | Обычно экземпляр или тип |
|---|---|---|---|---|---|
| `focal_length_param_name` — «Параметр фокусного расстояния» | фокусное расстояние объектива — вход расчёта угла обзора | «Длина» (→ мм) или «Число» (уже мм) | 1…50 мм; варифокал 2.8–12 мм — берётся текущее значение | **да** | **экземпляр** (у вариофокального объектива сфокусировано по месту) |
| `sensor_format_param_name` — «Параметр формата матрицы» | текстовое значение формата матрицы (как поле «Формат матрицы» ниже) — второй вход расчёта угла | «Текст» | см. таблицу форматов ниже | нет (иначе общий `sensor_format`) | тип |
| `distance_param_name` — «Параметр дальности» | максимальный радиус зоны (дальняя граница, если не ограничена расчётом по конусу) — заявленная дальность камеры, не оптика | **«Длина»** | 1…100 м; типично 8–40 м | **да** | тип |
| `height_param_name` — «Параметр высоты установки» | высота монтажа камеры над её уровнем | «Длина» | 2…12 м; типично 2.5–4 м. Пусто → «отметка точки вставки − отметка уровня» | нет | **экземпляр** (у каждой камеры своя высота) |
| `rotation_param_name` — «Параметр поворот камеры» | угол разворота камеры ВНУТРИ семейства (когда сам экземпляр не поворачивается) | «Угол» / «Число» | 0…360°. Прибавляется к направлению против часовой стрелки | нет | **экземпляр** |
| `tilt_param_name` — «Параметр наклона оптической оси вниз» | угол наклона оси камеры вниз от горизонта | «Угол» / «Число» | 0…90°; 0 = смотрит горизонтально; типично 10–35° | нет | **экземпляр** |

Горизонтальный и вертикальный угол обзора в этой таблице **нет** — они
не параметры, их не вписывают вручную, они считаются из фокусного
расстояния и формата матрицы (см. ниже). Если параметр из таблицы **не
типа «Длина»/«Угол»**, а «Число» — значение берётся как есть: длины
считаются в миллиметрах, углы — по полю «Единицы углов» (`angle_unit`;
на расчёт угла обзора это поле не влияет — оптика всегда даёт радианы).

### Как считается угол обзора

1. `focal_length_param_name` ищется на камере (экземпляр, потом тип).
   Не нашёлся/пустой/нечисловой — статус `no_optics`.
2. Формат матрицы: сначала `sensor_format_param_name` на камере
   (экземпляр, потом тип), если его там нет/не распознан — общий
   `sensor_format` из настроек. Не нашёлся ни там, ни там — `no_optics`.
3. `hfov = 2·arctg(ширина / (2·f))`, `vfov = 2·arctg(высота / (2·f))` —
   оба сразу, одним расчётом.

### Почему может не быть мёртвой зоны («конус строится прямо от камеры»)

Мёртвая зона (кольцевой вырез вокруг камеры) считается, только если
**оба** параметра — `height_param_name` и `tilt_param_name` — нашлись
(на экземпляре или на типе) и дали значение (вертикальный угол для
формулы уже посчитан оптикой, см. выше). Если хоть один не нашёлся —
зона строится плоским сектором прямо от точки камеры, без выреза. Самая
частая причина — один из этих параметров был параметром **типа**, а
кнопка проверяла только экземпляр и не находила его. В отчёте по каждой
камере печатается явно, что использовано: `h=3.00 м, наклон=45°,
верт.угол=30°`, либо `мёртвая зона не считается (не найдено: наклон)` —
по этой строке сразу видно, чего не хватает. Наклон, кстати, можно не
подбирать руками — см. кнопку «Навести на помещение» ниже.

## Проверка построения зоны — тестовые значения

Чтобы сверить построенную зону с расчётом руками, впишите одной тестовой
камере (`height_param_name` / `tilt_param_name` / `focal_length_param_name`
/ `distance_param_name` должны быть уже заполнены именами в настройках,
`sensor_format` — общим текстом в настройках; значения ниже — на самой
камере):

| Параметр на камере / в настройках | Значение |
|---|---|
| формат матрицы (`sensor_format` в настройках) | `6x4.5` (явные Ш×В в мм — круглые числа для проверки, не формат конкретной матрицы) |
| фокусное расстояние (на камере) | `3 мм` |
| дальность | `20000 мм` (20 м — заведомо больше расчётной дальней границы, чтобы её не обрезало) |
| высота установки | `3000 мм` (3 м) |
| наклон оптической оси вниз | `45°` |
| поворот камеры (если используется) | `0°` (для первой проверки — чтобы азимут совпал с направлением семейства) |
| высота плоскости расчёта (`target_level_offset_mm`, в настройках) | `0` (пол) |

Расчётные углы при этих числах:

```
hfov = 2·arctg(6 / (2·3))   = 2·arctg(1.0)   = 90.0°
vfov = 2·arctg(4.5 / (2·3)) = 2·arctg(0.75)  = 73.7°
```

Отчёт по камере должен показать ровно `угол 90°` и `верт.угол=74°`
(округление до целых, точное значение — 73.74°). Дальняя/ближняя граница
конуса при `h=3 м`, `наклон=45°`, `верт.угол/2=36.87°`:

```
near = h / tg(наклон + верт./2) = 3 / tg(81.87°) = 3 / 7.0007 = 0.4286 м
far  = h / tg(наклон − верт./2) = 3 / tg(8.13°)  = 3 / 0.1429 = 21.00 м
```

`far` (21.00 м) больше заданной дальности (20 м) — сработает
предохранитель «дальняя граница не может быть больше `distance_param_name`»,
реальная дальняя граница будет **20.00 м**, а не 21.00 м (проверьте это
тоже — хороший тест на предохранитель). Итоговая зона — кольцевой сектор
шириной 90°, от **0.43 м** до **20.00 м**. Отчёт по камере:
`R 0.4–20.0 м; h=3.00 м, наклон=45°, верт.угол=74°`. Проверяется в самом
Revit инструментом «Измерить» (`Measure`) от точки вставки камеры до
ближней и дальней дуги контура.

Если вместо кольца получился сплошной сектор от самой точки камеры
(`R 0.0–…`) — высота или наклон не нашлись; смотрите `cone_note` в
отчёте (см. выше) — там написано, чего именно не хватает. Если вместо
угла 90°/74° в отчёте другие числа — проверьте, что формат матрицы и
фокусное расстояние действительно те, что вписаны (возможно, они нашлись
на ДРУГОМ уровне — экземпляр вместо типа или наоборот, см. `_find_param`).

Дальше меняйте по одному параметру и пересчитывайте руками:
- **`наклон=0°`** (камера смотрит горизонтально) → `near = 3/tg(36.87°) =
  4.00 м`, `far → ∞` (в реальности упрётся в 20 м дальности).
- **фокусное `6 мм`** (вдвое больше) → `hfov = 2·arctg(6/12) = 53.13°`,
  `vfov = 2·arctg(4.5/12) = 41.11°` — оба угла уже, дальность видимости
  при том же наклоне больше (типичный эффект более длиннофокусного
  объектива — уже, но дальше).

## Потолочные камеры, смотрящие почти строго вниз (купольные)

Модель кнопки — это **направленный клин**: камера смотрит в одну сторону
по горизонтали (азимут), в этой стороне отсекается кольцевой сектор по
наклону/вертикальному углу. Это верно для камер, направленных **по
диагонали вниз** — уличные/потолочные поворотные, угловые, «бочонок»
вдоль коридора: `наклон` там разумно в пределах 10–60°.

Для классической **купольной камеры на потолке, смотрящей строго или
почти строго вниз** (`наклон` близко к 90°) эта модель перестаёт быть
физичной: у формулы `near = h / tg(наклон + верт./2)` при
`наклон + верт./2 ≥ 90°` тангенс уходит в минус — код обрежет
результат до 0 (мёртвая зона пропадает), что для камеры, направленной в
надир, отчасти верно (она видит точку прямо под собой без выреза), но
**зона всё равно рисуется узким клином по горизонтальному углу**, хотя у
камеры, смотрящей строго вниз, охват физически представляет собой
**круг** вокруг точки установки (или полный, если объектив/купол
круговой обзор, или широкий сектор — зависит от модели камеры), а не
узкий клин.

**Решение по вашим камерам**: они купольные, но с поворотным объективом
(пан/тилт внутри купола) — то есть направление и наклон у них не
зафиксированы «в надир», а настраиваются под конкретную точку монтажа,
как и у обычной направленной камеры. Отдельный круговой/надирный режим
поэтому не добавлялся — направленная модель (клин + кольцевой сектор)
подходит и для них, если `tilt_param_name`/`rotation_param_name`
отражают реальный текущий поворот объектива. Именно для подбора этого
наклона под конкретное помещение — следующий раздел.

Если у какой-то конкретной камеры объектив всё же зафиксирован строго
вниз (наклон ~80–90°) — не указывайте `tilt_param_name` для неё (оставьте
поле пустым на конкретном экземпляре): зона строится плоским сектором
радиусом `distance_param_name`, без мёртвой зоны и без деления по
наклону. Ширина сектора при этом — по-прежнему расчётный `hfov`.

Важная оговорка: раз угол обзора теперь всегда расчётный (по обычной
формуле «точечной камеры», `2·arctg(размер/2f)`), для настоящего
**рыбьего глаза** (fisheye, честные 180–360° по горизонтали) она не
подходит принципиально — такая формула физически не может дать больше
~180° ни при каком фокусном расстоянии, реальные fisheye-объективы
считают по другой проекции (эквидистантной и т.п.). Если среди ваших
купольных камер есть настоящие fisheye — для них зона обзора этой
кнопкой будет занижена; скажите, если это ваш случай, добавлю отдельную
формулу для fisheye.

## Автонаведение: кнопка «Навести на помещение»

Вторая кнопка панели `SOT.panel/AimCameras`. Она не строит зону — она
**подбирает и записывает наклон** (а если фокусное — параметр экземпляра,
то и **фокусное расстояние**) каждой выбранной камеры так, чтобы дальний
край её конуса приходился на границу помещения по направлению взгляда, а
не куда придётся:

```
наклон = arctg(высота / расстояние_до_стены) + вертикальный_угол/2
```

где `расстояние_до_стены` — не расстояние до ближайшей стены вообще, а
расстояние от камеры до границы её помещения **вдоль луча, куда камера
смотрит** (тот же азимут — `FacingOrientation` + `rotation_param_name` +
`direction_offset_deg`, что и у «Зон обзора»). Высота берётся как есть
(параметр камеры — экземпляр или тип, либо отметка точки вставки); если
не нашлась нигде — записывается значение по умолчанию `auto_default_height_mm`
(раздел ⑥) в `height_param_name` (если он есть на экземпляре) — чтобы
«Зоны обзора» потом взяли ту же высоту.

### Автоподбор фокусного расстояния

Если `focal_length_param_name` найден на камере как параметр **именно
экземпляра** (вариофокальный объектив — см. таблицу параметров выше),
кнопка сначала подбирает и **записывает** его, и только потом считает
наклон по уже подобранному вертикальному углу:

1. Дальняя точка — та же, что для наклона (луч по азимуту камеры до
   границы помещения).
2. Ширина помещения **в этой точке** — два луча перпендикулярно
   направлению взгляда (влево/вправо) до границы помещения, из точки чуть
   ближе дальней стены (чтобы не оказаться ровно на границе).
3. Требуемый горизонтальный угол обзора — чтобы эта ширина целиком
   поместилась в кадр на дальней точке:
   `hfov = 2·arctg((ширина/2) / расстояние_до_стены)`.
4. Требуемое фокусное — обратная формула оптики (см. выше):
   `f = ширина_матрицы / (2·tg(hfov/2))`, ограничивается диапазоном
   `auto_focal_min_mm`…`auto_focal_max_mm` (раздел ⑥, непрерывный
   вариофокал) и записывается на камеру.
5. Вертикальный угол для дальнейшего расчёта наклона берётся уже из
   ЗАПИСАННОГО фокусного (обычный `_optical_fov`, как у «Зон обзора»).

Если фокусное — параметр только ТИПА, имя не задано, ширину помещения не
удалось измерить (один из перпендикулярных лучей не встретил границу), или
формат матрицы не распознан — фокусное не трогается, вертикальный угол
берётся из того значения, что уже стоит на камере (прежнее поведение, без
регресса); если и оптика не нашлась вовсе — `auto_default_vfov_deg` только
для расчёта наклона в этот раз, никуда не записывается (это не параметр
камеры).

**Важно:** `tilt_param_name` для этой кнопки обязан быть параметром
**экземпляра**, не типа — иначе один прогон переставил бы наклон сразу у
всех камер этого типа (в разных помещениях с разной глубиной), что почти
никогда не нужно. Если он параметром типа — кнопка отказывается писать,
статус `tilt_not_instance`, камеру пропускает.

### Предупреждение «поднимите камеру»

После расчёта наклона кнопка проверяет два порога (раздел ⑥):

- получившаяся ближняя мёртвая зона (`near = h / tg(наклон + верт.угол/2)`)
  больше `auto_max_near_zone_mm`;
- получившийся наклон больше `auto_max_tilt_deg`.

Если сработало хотя бы одно — наклон/фокусное всё равно записываются
(камера не остаётся ненаведённой), но статус становится `ok_warn`, а в
отчёте — явная причина и числа против порогов. Точная «на сколько выше
поднять» не считается (уравнение не имеет простого решения в замкнутом
виде) — ориентируйтесь по цифрам в отчёте. Оба порога — про одно и то же:
геометрически поднятие камеры (при том же дальнем крае обзора) уменьшает
мёртвую зону и требует меньшего наклона.

Порядок использования: **сначала «Навести на помещение»** (наклон и,
возможно, фокусное записаны на камеры) **→ затем «Зоны обзора»** (по
свежим значениям рисуется зона). Кнопка автонаведения ничего не рисует
сама.

Отчёт по каждой камере (окно вывода pyRevit) показывает, что именно
получилось: `до стены 5.20 м, h=3.00 м, верт.угол=30° -> наклон 45.0°;
ширина помещения 4.10 м -> фокусное 3.20 мм`. Статусы: `ok` / `ok_warn`
(см. выше), `no_room` (не нашлось помещение — см. раздел про поиск
помещений выше), `no_wall_hit` (луч по направлению камеры не пересёк
границу помещения в разумных пределах — проверьте направление/поворот),
`missing_inputs` (нет ни высоты, ни значения по умолчанию, либо то же
для вертикального угла), `tilt_not_instance`/`tilt_readonly` (см. выше).

### Проверка автоподбора вручную

На тестовой камере (те же настройки оптики, что в разделе «Проверка
построения зоны обзора» выше — `sensor_format=6x4.5`,
`auto_focal_min_mm=1`, `auto_focal_max_mm=50`, высота `3000 мм`) в
прямоугольном помещении, где вдоль луча взгляда камеры до дальней стены
`5000 мм`, а ширина помещения в этой точке `8000 мм`:

```
hfov (требуемый)  = 2·arctg(4/5)      = 2·arctg(0.8)   = 76.7°
фокусное          = 6 / (2·tg(38.37°)) = 6 / 1.585      = 3.79 мм
```

Записанное фокусное должно быть **≈3.79 мм** (если в диапазоне
`auto_focal_min_mm…auto_focal_max_mm`, иначе — клампленное к границе
диапазона, отчёт это отметит отдельно). Дальше вертикальный угол и наклон
считаются, как в разделе «Проверка построения зоны», уже по этому
фокусному.

## «Не выбирается ни одна камера» — что проверить

1. **Категория семейства камеры.** Выделите камеру в модели → на панели
   «Свойства» вверху написана категория. Если это не «Оборудование систем
   безопасности», а, например, «Устройства связи», «Информационные
   устройства», «Электрооборудование» или «Обобщённые модели» — впишите
   соответствующее имя (`OST_CommunicationDevices` / `OST_DataDevices` /
   `OST_ElectricalEquipment` / `OST_GenericModel`) в поле
   `camera_categories` (Shift+клик), можно несколько через запятую.
2. **Тип активного вида** — план этажа/потолка или чертёжный вид. На 3D,
   разрезе, фасаде, листе, легенде, спецификации кнопка не работает.
3. **Обязательные настройки** — заполнены `distance_param_name`,
   `focal_length_param_name`, `zone_tag` и формат матрицы (`sensor_format`
   или `sensor_format_param_name`).

## Отчёт по каждой камере

После запуска в окне вывода pyRevit печатается строка на **каждую**
выбранную камеру: маркер (`OK` / `~` — построена без обрезки / `FAIL`),
кликабельная ссылка на элемент, имя типа и марка, статус и подробность.

Для построенных зон подробность — сводка расчёта:
`азимут 137°, угол 72°, R 0.0–18.3 м; напр.: FacingOrientation + поворот 25.0°; обрезка по помещению: помещение (1 по XY) (312 сегм.)`.
По ней видно, тем ли направлением пошла зона и как нашлось помещение
(число сегментов включает внутренние контуры — «дыры» от колонн).

| Статус | Причина / что делать |
|---|---|
| `построена` | зона создана и обрезана по помещению |
| `построена (без обрезки — помещение не найдено)` | под точкой камеры нет `Room` ни в одной связи |
| `построена (без обрезки — обрезка дала пустой контур)` | камера впритык к стене или подхватилось чужое помещение — построено без обрезки |
| `нельзя посчитать угол обзора (фокусное/матрица)` | подробность уточняет причину: не задано имя параметра фокусного расстояния, параметр не найден на камере, он не числовой, фокусное = 0, либо формат матрицы не задан/не распознан ни на камере, ни в настройках |
| `нет параметра дальности` | у камеры нет параметра `distance_param_name` |
| `вырожденная геометрия` | подробность уточняет: `расчётный угол обзора = 0…` (что-то не так с фокусным/матрицей несмотря на найденные параметры), `дальность = 0…` (пуст / не «Длина»), `не удалось определить направление [Facing=… / BasisY=… / …]` (векторы для диагностики) |
| `нет точки вставки` | у камеры `Location` не `LocationPoint` |
| `ошибка создания` | `FilledRegion.Create` отклонил контур — увеличьте `ray_count` или упростите помещение |

### Если все зоны смотрят в одну сторону

Камеру разворачивают параметром внутри семейства, а не поворотом
экземпляра. Впишите имя этого параметра в `rotation_param_name`
(Shift+клик). Проверить: в отчёте азимут у разных камер должен стать
разным.

### Если помещения не находятся (все зоны «без обрезки»)

В строке отчёта после «без обрезки —» написана причина:

| Текст в отчёте | Что это значит |
|---|---|
| `в проекте нет связей (RevitLinkInstance)` | архитектурная модель не подгружена как связь Revit |
| `связи есть, но не загружены` | связь в статусе «Выгружено» — Управление связями → Загрузить |
| `в связях (N шт.) нет размещённых помещений` | в связанной модели помещения не расставлены, либо это не та связь (МЭП/КЖ вместо АР) |
| `проверено помещений: N, точка вне всех контуров по XY` | камера по плану вне помещений: вынесена в стену/шахту дальше 90 мм, стоит в коридоре без помещения, или связь смещена/повёрнута относительно площадки (иная система координат) |
| `помещение (из N по XY — ближайшее по высоте)` | помещение найдено, но отметка камеры не попала в габарит ни одного этажа — проверьте отметку установки и «Базовое смещение»/«Смещение сверху» помещений |

Помещения берутся из **всех** загруженных связей — отдельно указывать
файл не нужно. Категория — стандартные «Помещения» (`OST_Rooms`) связи.

### Если у конкретного помещения контур так и не строится

Значит не сработал ни `GetBoundarySegments`, ни резервное сечение тела
(`_room_solid_rings`) — у помещения нет вычисленной геометрии вовсе.
Обычно значит, что оно по-настоящему **не ограничено** (Revit показывает
жёлтый штрих вместо заливки на плане: разрыв в стенах, не расставлены
разделители помещений). Исправляется в архитектурной модели, не в
настройках кнопки.

### Колонны не создают тень в зоне

Тень от колонны берётся не отдельной обработкой, а прямо из границы
`Room`: колонна должна иметь отделку (в архитектурной модели),
отмеченную **«граница помещения»** — тогда сам Revit вырезает её контур
внутри `Room` и `GetBoundarySegments` отдаёт его дополнительным
внутренним контуром. Если тени нет:

- проверьте в самом Revit, что у отделки колонны включена «граница
  помещения» (свойство элемента, которым обёрнута колонна, — не
  конструктивной колонны как таковой);
- убедитесь, что после этого помещение **пересчитано** (переставьте его
  или откройте на редактирование границ и подтвердите) — Revit не всегда
  обновляет контур сам;
- в отчёте по камере смотрите число сегментов после «обрезка по
  помещению: … (N сегм.)» — оно должно вырасти, когда у помещения
  появляется внутренний контур колонны.

### «Обрезка дала пустой контур»

Значит обрезка по границе помещения выродила контур в ноль, и кнопка
сама откатилась на «без обрезки» (статус `ok_clip_failed`). Частая
причина — слишком частая сетка вершин (сложная граница, много
внутренних контуров от колонн) давала соседние точки контура зоны
ближе, чем Revit готов принять для отрезка линии (`Line.CreateBound`
кидал исключение, и раньше это обрывало построение всего контура
целиком). Порог склейки близких точек увеличен (`_MIN_SEG_FT`, ~3 мм —
с запасом выше реального минимума Revit) и единичный проблемный отрезок
больше не роняет весь контур — пропускается, а не отменяет всё
построение. Зона в любом случае строится (кнопка не падает).

## Единицы (кратко)

- **Углы** (наклон, поворот): тип «Угол» → радианы; тип «Число» → по
  полю `angle_unit` (по умолчанию «авто» = градусы для «Числа»). Угол
  обзора (горизонтальный/вертикальный) сюда не относится — он не
  параметр, а результат расчёта, сразу в радианах.
- **Длины** (дальность / высота / фокусное): тип «Длина» → внутренние
  футы Revit пересчитываются автоматически; тип «Число» → трактуется как
  миллиметры.

## Вид как с камеры

Четвёртая кнопка панели `SOT.panel/CameraPreviewView`. Ничего не пишет на
саму камеру — создаёт (или, при повторном запуске на той же камере,
обновляет на месте — идемпотентно по имени вида `СОТ · {камера} · id{Id}`)
3D-перспективный вид Revit, поставленный в точку выбранной камеры и
смотрящий туда же, куда она: тот же источник направления и наклона, что у
«Зон обзора»/«Навести на помещение» (`FacingOrientation` +
`rotation_param_name` + `direction_offset_deg` для азимута,
`tilt_param_name` для наклона вниз). Высота глаза — так же, как высота
установки у зон обзора (`height_param_name`, либо отметка точки вставки
минус отметка уровня, либо `auto_default_height_mm`, если не нашлось
ничего).

**Поле зрения.** У Revit нет прямого API «задать угол обзора камеры» —
но crop box перспективного вида физически представляет собой сечение
пирамиды с вершиной в точке глаза, поэтому отношение половины
ширины/высоты crop box к глубине сечения одинаково на любой глубине.
Кнопка не трогает ближнюю/дальнюю плоскость (Z), которую Revit сам
выставил новому виду по умолчанию — только пересчитывает X/Y crop box на
уже имеющейся глубине под расчётный `hfov`/`vfov` этой камеры (фокусное
расстояние + формат матрицы, та же оптика, что у «Зон обзора»). Дальность
камеры (`distance_param_name`) для этого не используется — угол не
зависит от того, на какой глубине его мерить.

Если оптика на камере не настроена (нет фокусного/матрицы) — вид всё
равно создаётся/переставляется, просто со штатным полем зрения Revit
(статус `ok_no_optics`).

**Оговорка:** знак и точка отсчёта Z у `CropBox` перспективного вида в
Revit API задокументированы скупо — в этом окружении нет живого Revit,
чтобы прогнать кнопку и свериться глазами. При первом реальном запуске
сравните получившийся видимый угол вида с зоной обзора той же камеры
(«Зоны обзора» на плане) — если картинка выглядит растянутой/сплющенной
или направление кажется зеркальным, дело в знаке при пересчёте `up`/
`forward` или в трактовке `CropBox.Max.Z` в `build_camera_preview_view`
(`lib/lowlife/sot_fov.py`) — правка локальная, подход менять не нужно.

## Идеи для более точного расчёта (не реализовано)

- `ReferenceIntersector` с `FindReferencesInRevitLinks = True` по всем
  видимым элементам — честная трассировка лучей вместо готового контура
  `Room` (учла бы, например, колонну без отделки/без «границы
  помещения», мебель и т.п.); нужен 3D-вид.
- Булево пересечение тел (`BooleanOperationsUtils`) конуса и объёма
  помещения — точная обрезка с учётом высоты помещения/потолка.
