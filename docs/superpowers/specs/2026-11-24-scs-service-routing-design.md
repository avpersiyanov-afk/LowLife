# Универсальный служебный расчёт цепей — дизайн

## Цель

Создать на `Tools.panel` отдельный служебный набор для расчёта и маркировки цепей, который реализует все три направления и не изменяет текущие кнопки дисциплин:

1. исправляет ошибки текущих расчётов;
2. запускает полный цикл одной кнопкой «Рассчитать и маркировать цепи»;
3. использует геометрический граф как источник истины для маршрутов.

Архитектура должна быть пригодна для СКС, СКУД, СПС и СОУЭ. Различия систем задаются конфигурацией и адаптерами сбора цепей, а граф, поиск стояков, расчёт длины и маркировка остаются общими.

## Что остаётся без изменений

- текущие кнопки `SCS.panel`, `SKUD.panel`, `SPS.panel`, `SOUE.panel`;
- существующая схема настроек и параметры текущих кнопок;
- рабочие алгоритмы, пока служебная версия не будет проверена на моделях.

Все новые настройки получают отдельный префикс и отдельный файл конфигурации.

## Модель систем

Служебный расчёт работает с абстрактной цепью:

```text
Circuit {
    system_kind,
    circuit_id,
    panel_id,
    device_ids,
    start_point,
    end_points,
    route_mode,
    length_rules,
    marking_rules
}
```

Адаптер дисциплины отвечает только за сбор входных данных:

- **СКС** — обычно панель и одно устройство, но допускаются несколько устройств;
- **СКУД** — контроллер и несколько устройств;
- **СПС** — одна длинная цепь с большим количеством устройств и адресным порядком;
- **СОУЭ** — одна длинная цепь с большим количеством устройств, включая ветвления при необходимости.

Геометрический граф, стояки, поиск пути, длины и маркировка не должны содержать условий, завязанных на одну дисциплину.

## Единая кнопка

Главная кнопка `Tools.panel/ServiceCircuitCalculateAndMark` выполняет операции:

1. выбирает систему или набор систем;
2. загружает адаптер состава цепей;
3. проверяет настройки, трассы, шахты, панели и устройства;
4. собирает трассы со всех этажей;
5. строит геометрический граф;
6. находит шахты и вертикальные переходы;
7. определяет точки подключения панелей и устройств;
8. ищет маршруты для каждой цепи;
9. рассчитывает длины и разбивку по способам прокладки;
10. записывает адреса и предыдущие узлы как результат расчёта;
11. записывает длины, номера и маршруты в параметры;
12. обновляет служебную маркировку на плане;
13. выводит отчёт об ошибках, неоднозначностях и разрывах.

Отдельные диагностические кнопки:

- `ServiceCircuitGraph` — граф трасс;
- `ServiceCircuitRisers` — шахты и стояки;
- `ServiceCircuitLengths` — маршруты и длины;
- `ServiceCircuitMarks` — маркировка.

## Поиск маршрута для разных систем

### СКС и СКУД

Для каждого устройства строится отдельный путь от панели или контроллера. Общие участки маршрута могут использоваться несколькими устройствами. При нескольких устройствах результат хранит отдельный путь и длину для каждого устройства.

### СПС и СОУЭ

Цепь содержит последовательность устройств. Для каждой пары соседних устройств ищется путь по графу:

```text
панель → устройство 1 → устройство 2 → ... → устройство N
```

Общая длина цепи равна сумме длин участков между соседними устройствами. Если система работает как кольцо, добавляется путь от последнего устройства к панели или первому устройству по настройке.

Если адресный порядок отсутствует или содержит разрыв, используется геометрический порядок только при однозначном расположении устройств. Такой случай обязательно попадает в отчёт.

## Геометрический граф

Все линейные элементы трассы собираются со всех этажей. Концы и пересечения превращаются в вершины. Между соседними вершинами сохраняются рёбра с исходным `ElementId`, уровнем, типом прокладки и фактической длиной кривой.

Параметр «Предыдущий адрес» не участвует в поиске маршрута. Адрес и предыдущий адрес записываются после успешного расчёта как результат. Несколько цепей могут использовать одни и те же рёбра, при этом пути цепей хранятся отдельно.

Если путь не найден, цепь не получает фиктивную длину. В отчёт попадают система, цепь, начальный и конечный элементы, этажи, ближайшие разорванные компоненты и координаты места разрыва.

## Исправления текущей логики

### Нераспознанные участки

Участок без распознанного способа прокладки не исчезает из общей длины. Он учитывается отдельно как `unknown`, показывается в отчёте и по умолчанию считается трубой для расчётной оценки.

### Несколько устройств

Цепь с несколькими устройствами обрабатывается по правилам адаптера системы. Для СКС и СКУД строится отдельный маршрут к каждому устройству. Для СПС и СОУЭ используется последовательность устройств. Неоднозначные точки подключения попадают в отчёт.

### Идентификация панелей и контроллеров

Источники цепей сопоставляются по `ElementId` и идентификатору электрической системы. Имя используется только в отчёте и маркировке. Совпадающие имена не должны объединять цепи.

### Проверки и транзакции

До записи выполняются проверки целостности графа, конечных узлов, дубликатов, циклов, разрывов и соответствия адаптера системе. Очистка и запись адресов выполняются после успешной проверки в общей транзакции. При критической ошибке текущие данные не изменяются.

## Автоматическое определение стояков

Кандидатами считаются экземпляры семейства шахт, у которых имя типа содержит `СС`, `СБ` или `СПЗ`. В текущей модели найдено семейство `SMNX_GM_т_Шахта инж. коммуникаций` и типы `ВИС_СС`, `ВИС_СПЗ`, `ВИС_СС_СПЗ`.

Для каждой шахты используется её bounding box. Трасса считается входящей в стояк, если её XY-проекция пересекает область шахты или находится в заданном допуске.

- продолжение выше — направление `вверх`;
- продолжение ниже — направление `вниз`;
- продолжения в обе стороны — `вверх/вниз`;
- продолжение не найдено — шахта и ближайший сегмент попадают в отчёт как разрыв;
- несколько кандидатов — стояк помечается неоднозначным.

## Длины

Длина цепи является суммой длин рёбер маршрута и концевых подводов. Для прямых ортогональных участков используется сумма осевых составляющих. Для кривых используется длина кривой Revit.

Для каждого ребра сохраняются длина, способ прокладки, уровень, исходный `ElementId` и список цепей, использующих ребро.

## Маркировка

Служебная версия создаёт обновляемые элементы маркировки на активном плане. Для каждой системы показываются номер цепи, источник, устройства, общая длина, разбивка по способам прокладки и статус маршрута.

Для СПС и СОУЭ дополнительно показывается порядок устройств и длина каждого участка между соседними адресами. Для неполного маршрута маркировка содержит предупреждение и координату разрыва.

## Проверка

- чистые функции графа, стояков и длин покрываются тестами без Revit;
- через Revit MCP проверяются реальные уровни, шахты, лотки, панели, контроллеры и цепи;
- отдельно проверяются несколько цепей по одному маршруту;
- отдельно проверяются многоприборные цепи СКУД;
- отдельно проверяются длинные цепи СПС и СОУЭ;
- отдельно проверяются кольцевые и разорванные маршруты;
- существующие тесты проекта должны продолжить проходить без изменений.
